# Как вносить изменения в OG CRE8R²

Короткая памятка для людей и ИИ-агентов. Она не заменяет источники истины, а ведёт к ним.

## Сначала прочитать

1. [Журнал проекта](docs/ROADMAP-2026-11-07.md): актуальный срез и связанные пункты. Это единая память решений и состояния, второй общий список задач не заводим.
2. [AGENTS.md](AGENTS.md): порядок работы до, во время и после задачи.
3. [Выпуск и обслуживание](docs/OPERATIONS.md): проверки, публикация, откат.
4. [DESIGN.md](DESIGN.md), если меняется интерфейс.

## Окружение

- Node 24 (в CI 24.19.0). Для полного прогона нужны Python 3.12+ и FFmpeg с FFprobe.
- `npm ci`, затем `npm run dev`. Вне Telegram приложение открывается в демо, на проде демо доступно по `/?demo`.
- Ключей Supabase и токена бота во фронтенде нет и быть не должно. Для браузера разрешён только публичный `VITE_API_URL`.

## Порядок работы

1. Ветка от свежего `origin/main`. Одна задача, один pull request.
2. До существенной реализации запишите в журнал план, baseline, критерий приёмки, совместимость и риски.
3. Делайте изменение и тесты к нему. Работающие эффекты, данные, награды и правила доступа сохраняются.
4. Перед pull request выполните `npm run test:all` на окончательном коде. Для интерфейса проверьте в браузере основной, повторный и прерванный сценарий, Back и Close, обе темы, ширину 320 и 390, клавиатуру.
5. После проверки обновите запись в журнале: что сделано, что не сделано, что не проверено.

`main` защищён: слияние только через pull request и после четырёх проверок (verify, Master platform and client templates, Edge API and release tools, Edge API typecheck).

## Что обязательно

- Непроверенное называйте NOT VERIFIED. «Подготовлено», «в main», «frontend выпущен», «backend выпущен» и «проверено пользователем» это разные состояния.
- Выкладка фронтенда не выпускает Edge API и миграции. Если они нужны, опишите это в pull request отдельно.
- XP, уровни, серию и доступ начисляет только сервер. Локальная отметка не заменяет серверный результат.
- Не рисуйте фиктивные ответы API, начисления и зелёные проверки. Демо не является настоящим аккаунтом.

## Чего в репозитории быть не должно

- Секретов, токенов и содержимого приватных окружений.
- Персональных данных учеников и текстов их работ.
- Полных текстов платных уроков: они ведутся в закрытом хранилище и отдаются через API после проверки доступа.
- Собранных файлов: `dist`, `test-results`, `*.tsbuildinfo`.

## Тексты

Интерфейс обращается к человеку на «ты». В авторском русском тексте нет длинных тире. Новости короткие, с применением и проверенными первоисточниками. Проверить текст на штампы и тире: `npm run copy:check -- <файл или папка>`.

## Границы подсистем

OG, Academy, `Azelkhanov-master` и `src/platform-kit` разворачиваются независимо, их статус не наследуется. В переносимом мастере действует его собственный `AGENTS.md`.
