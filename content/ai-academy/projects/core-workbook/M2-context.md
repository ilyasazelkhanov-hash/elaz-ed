## L1 · Файлы, контекст и поиск перед ответом

**Маленький шаг:** сравни [текущий документ](examples/current-public-rules.md) и [архивный](examples/archive-public-rules.md). Найди разницу в порядке подтверждения, укажи ID и версии.

1. Нарисуй два маршрута: «вставил нужный фрагмент → запрос» и «поиск выбрал фрагмент → запрос».
2. Если загрузил файл в инструмент, попроси указать один конкретный пункт и сверь его с оригиналом. Факт загрузки не доказывает чтение всех страниц.
3. Запиши, какие части действительно были доступны. Поиск перед ответом часто называют RAG; он не изменяет автоматически обучение модели.

## L2 · Что разрешено передавать

**Маленький шаг:** открой [реестр риска данных](data-risk-register.csv). До загрузки опиши цель и минимально нужные сведения.

1. Разбери пять собственных учебных объектов: публичное правило, картинку, письмо, таблицу и ключ доступа. Реальные секреты в файлы не вставляй.
2. Отметь происхождение, право использования, инструмент и неизвестные условия хранения.
3. Подготовь безопасный вымышленный вход. При неизвестном разрешении оставь объект на уточнение, а не давай ему зелёный статус.

**IP** — права на интеллектуальную собственность. Условия исходной картинки и условия результата инструмента проверяются отдельно. Замена имени псевдонимом не гарантирует невозможность узнать человека.

**Маленький шаг:** выбери одно фактическое нарушение из M1. Сохрани копию запроса v2 и запиши, какое наблюдение должно измениться.

| Вход | Нарушение v1 | Одно изменение запроса | Проверка v2 на том же входе | Новый вход для проверки переноса | Статус |

| | | | | | not_run |

После исправления повтори прежний случай и один новый. **Self-check** — самопроверка, которую можно попросить выполнить и у модели. Её заключение не заменяет твою сверку с источником.

Переработай сценарий так, чтобы убрать ненужные данные или внешнее действие. Не заявляй о проведённом согласовании, если пока подготовлена только форма.

- [ ] Извлечение сведений сверено с оригиналом либо обозначено not_run.
