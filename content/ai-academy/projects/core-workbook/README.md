# Рабочая тетрадь AI Core · CORE-000

Здесь начинающий собирает свою первую проверяемую работу: запрос, фактический ответ, исправления и основания. Тетрадь дополняет 16 занятий CORE-000. Скачивание и заполненная галочка не дают зачёт в мини-аппке.

Все примеры вымышлены. Мы используем библиотеку **«Соседняя полка»**, а не мастерскую из оцениваемой работы курса. Здесь нет готовых ответов модели, ключей квизов, настоящих участников или подтверждений публикации.

## Начать за пять минут

1. Распакуй архив в отдельную папку. Открой `README.md` в текстовом редакторе; Markdown — обычный текст с заголовками и таблицами. Интернет и установка программ для чтения не нужны.
2. Сохрани свою копию файлов. Начни с [модуля 1](M1-basics.md): сначала запиши цель и неизвестное, затем заполни [шаблон запроса](prompt-template.md).
3. Прочитай [разрешённый текущий контекст](examples/current-public-rules.md). Ничего не добавляй к неизвестным часам, адресу или стоимости.
4. Если используешь разрешённый AI-инструмент, сохрани точный вход и полный полученный ответ в своей копии папки `runs`. Сначала проверь его сам. Аккаунт, доступ и возможная стоимость зависят от выбранного сервиса.
5. Заполни [журнал](run-log.csv). Значение `not_run` означает **«не запускался»**; меняй его только после фактического действия. Без AI-доступа продолжай подготовку офлайн, но не называй план выполненным запуском.

**Промпт** — текст задания AI. **Контекст** — сведения, реально доступные в конкретном запросе. **Артефакт** — сохраняемый результат работы: файл, таблица, ответ, схема или журнал проверки.

## Как читать CSV-таблицы

CSV — обычная текстовая таблица: первая строка содержит названия столбцов, следующие — записи. Открывай в редакторе текста или таблиц, сохраняя свою копию. Исходные пустые поля не означают выполненную проверку.

В `run-log.csv`: `run_id` — ID запуска; `lesson_code` — код урока; `date` — фактическая дата; `product` — приложение; `model_or_undisclosed` — показанная модель либо «не раскрыта»; `tool_settings` — включённые возможности; `prompt_file`, `input_file`, `result_file` — пути к запросу, данным и ответу; `errors` — найденные нарушения; `review_minutes` — минуты проверки; `state` — состояние, начиная с not_run («не запускался»).

В реестре риска: `object_or_action` — объект или действие; `purpose` — цель; `provenance` — происхождение; `minimum_required_data` — минимально нужные сведения; `tool_or_destination` — инструмент или получатель; `permission_evidence` — основание разрешения; `possible_event` и `possible_harm` — событие и возможный вред; `control` — мера проверки; `owner` — ответственный; `next_step` — следующий шаг. `not_reviewed` означает «ещё не проверено».

## До работы с инструментом

Используй только вымышленные сведения из этой папки либо данные с понятными разрешениями. Не вставляй реальные переписки, пароли и ключи. Архивный документ предназначен для упражнения на конфликт версий, а не для клиентского ответа. Все отправки и публикации в этой тетради остаются планом; автоматической рассылки нет.

Неизвестное сохраняй как **«неизвестно»**. Не подставляй ноль вместо отсутствующей цены и не придумывай срок ради красивого ответа. Даже уверенный ответ требует сверки с источником.

## Пересобрать архив (необязательно)

Для обычного прохождения Python не нужен. Авторская упаковка использует только стандартную библиотеку Python 3:

```bash
python3 pack.py --output ../core-workbook.zip
```

Архив включает явный список файлов и фиксированные метки времени. Он не собирает твои личные ответы из `runs`. Свои материалы храни отдельно от исходного шаблона и передавай только по правилам курса.
