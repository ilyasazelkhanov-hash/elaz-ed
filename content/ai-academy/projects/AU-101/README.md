# AU-101: визуальная лаборатория

Для локальной лаборатории нужен браузер и HTTP-сервер. В распакованной папке выполните:

```bash
python3 -m http.server 5190 --bind 127.0.0.1
```

Откройте локальный порт 5190. Настройки меняются флажками и списками, код редактировать не нужно. Проверяйте ID REQ-001, пустой email, повтор ID, ошибку таблицы и сбой после записи. Строки и черновики живут в памяти страницы и исчезают после перезагрузки. Настоящие AI, почта, CRM и Telegram не вызываются. Выходы модели — явно подписанные записанные образцы.

Разработческая проверка логики на Node.js 24:

```bash
node --test workflow.test.mjs
```

## Пример n8n

`n8n-workflow.json` — неактивная схема без credentials и внешних действий. Импортируйте её в свой n8n и изучите четыре узла: ручной запуск, учебный JSON, фильтр email и черновик результата. Удалите email в узле входа и сравните ветку фильтра. Результат узла не является постоянной таблицей и не означает доставку сообщения. Для сохранения и доставки нужно отдельно подключить разрешённые сервисы и проверить их доступы.

Схема исполнена в n8n 2.44.7 на Node.js 24: корректный вход дошёл до черновика, пустой email — до ветки отказа. Для повторения автоматической проверки установите n8n отдельно от учебного проекта и передайте путь к исполняемому файлу:

```bash
N8N_BIN=/path/to/n8n node verify-n8n.mjs
```

Проверка создаёт временную базу n8n, импортирует обе версии схемы, проверяет выходы и удаляет временные данные. Она не использует существующую пользовательскую базу. Не публикуйте сырой вывод n8n: он может содержать внутренние токены выполнения.
