# Мастер рядом · первая практика VC-101

Работающее учебное приложение из программы VC-101: три услуги, форма, проверка ввода и подтверждение **«Сохранено на этом устройстве; мастеру не отправлено»**. Внешних AI-вызовов, учётных записей, отправки сообщений, оплаты и настоящих заявок мастерам нет. Используй только вымышленные имя и контакт.

## Запуск за два шага

1. Распакуй архив и открой терминал в папке `first-app` — там, где лежит `server.mjs`.
2. Выполни:

```bash
node --version
node server.mjs
```

Нужен Node.js 24. Устанавливать npm-пакеты не требуется. Открой **http://127.0.0.1:8766/**. Для остановки сервера нажми Ctrl+C в том же терминале. Если порт занят, используй другой свободный порт:

```bash
FIRST_APP_PORT=8767 node server.mjs
```

Альтернатива при установленном Python 3: `python3 -m http.server 8766 --bind 127.0.0.1` в этой папке. Сам HTML через `file://` не запускай: браузеру нужен HTTP-адрес для модулей JavaScript.

Копия для просмотра в приложении: `/learning/academy/first-app/index.html`. Хранилище привязано к адресу сайта: копия на другом порту или другом сайте не читает ту же заявку.

## Своя версия на React по урокам курса

В архиве также есть `react-starter` — отдельный начальный React/Vite-проект с закреплёнными версиями. Готовая копия выше показывает нужное поведение без сборки; каркас React предназначен для твоей реализации. Это разные команды запуска.

Для уроков про компоненты, состояние, `npm run build` и `preview` открой терминал в `react-starter`, выполни `npm ci`, затем `npm run dev`. Нужны Node.js 24 и интернет для первой установки. Сборка: `npm run build`; просмотр собранного результата: `npm run preview`. Подробности в [инструкции каркаса](react-starter/README.md). В исходной папке без package.json эти npm-команды не запускаются.

## Первый проход

1. Выбери **«Установка светильника»**. Подпись над полями должна измениться.
2. Введи **«Учебная Алия»** и **`student@example.test`**. Это учебные значения, не настоящий контакт.
3. Нажми **«Сохранить на этом устройстве»**. Сравни услугу, имя и контакт с подтверждением.
4. Обнови страницу. Подтверждение должно остаться с тем же временем записи.
5. Объясни своими словами: запись сохранилась в браузере, но мастер её не получил. Время записи в браузере не является назначенным временем визита.

## Проверь ошибку

Нажми «Новая учебная заявка». Введи имя из пробелов и контакт `ab`, затем попробуй сохранить. Должны появиться понятные ошибки у полей; сохранённый результат не подменяется неуспешным вводом. Исправь данные и повтори.

Для отказа хранилища открой **«Учебная проверка ошибки»**, включи **«Имитировать отказ хранилища»** и отправь корректный ввод. Форма должна сообщить об отказе, сохранить введённые значения и не показать новое подтверждение. Отключи опцию и повтори. Это явно заданная учебная имитация, не сообщение об отказе настоящего сервиса.

Для проверки повреждённой записи можно в DevTools → Application/Storage → Local Storage заменить значение `master-request-v1` на `{broken` и обновить страницу. Приложение покажет пустую форму и объяснение, что запись не прочитана. Восстановления неизвестных данных нет.

## Контракт данных и состояния

- `serviceId`: только `tap`, `light`, `inspect`.
- `name`: строка 2–60 символов после удаления крайних пробелов.
- `contact`: строка 3–80 символов после удаления крайних пробелов. Проверяется длина, а не существование телефона или адреса.
- `createdAt`: момент успешной локальной записи в ISO-формате, не время визита.
- Ключ хранилища: `master-request-v1`. Хранится **только последняя** успешно сохранённая заявка. Следующая заменяет предыдущую.
- Состояния: редактирование → сохранение → подтверждение либо ошибка. При ошибке успех не рисуется.

Нажатие «Новая учебная заявка» открывает пустую форму, но не удаляет последнюю сохранённую запись. Для удаления есть отдельная кнопка. Удаляется только этот учебный ключ, не все данные браузера. Значения выводятся как текст, а не как HTML. Несколько вкладок не координируются; здесь нет синхронизации между устройствами и защищённого хранения личных данных.

## Проверки и файлы

```bash
node --test request.test.mjs
```

Проверки: три услуги и границы ввода; снимок после записи и повторное чтение; замена только последней успешной записи; отказ хранилища; повреждённый JSON; вывод текстовых данных; удаление только учебного ключа; отсутствие серверного API приёма.

| Файл | За что отвечает |
| --- | --- |
| `index.html` | Подписи, форма, каталог и подтверждение |
| `style.css` | Мобильная и широкая раскладка, видимые ошибки и фокус |
| `app.mjs` | Смена состояний, обработчики и вывод текста |
| `request.mjs` | Проверка полей и работа с одним ключом localStorage |
| `server.mjs` | Маленький локальный сервер только для чтения учебных файлов |
| `request.test.mjs` | Исполняемые проверки контракта |

## Границы и следующий этап

Этот пример подтверждает только локальный цикл. Для настоящего приёма обращений понадобятся серверное хранение, согласованные доступы и обработка персональных данных, подтверждённое уведомление сотруднику, обработка повторов и наблюдение за ошибками. Расписание, оплата и личный кабинет не добавляются одним переименованием кнопки. Не публикуй настоящие контакты и не вставляй секреты в frontend.

Для своей доработки выбери один маленький шаг, назови ожидаемое поведение до правки, повтори обычный и ошибочный ввод и сохрани фактические наблюдения. Готовая учебная копия сама по себе не является твоей итоговой работой.

Опциональное воспроизведение скриншотов для разработчика: `node capture.cjs` при доступных Playwright и системном Chromium `/usr/bin/chromium`. Это дополнительный инструмент среды, а не зависимость приложения; для обычного запуска и тестов он не нужен.

Разработчику: `python3 pack.py` пересобирает публичную копию по списку `index.html`, `style.css`, `app.mjs`, `request.mjs` и ZIP из исходной папки. Это дополнительная команда упаковки; для работы приложения Python не требуется.
