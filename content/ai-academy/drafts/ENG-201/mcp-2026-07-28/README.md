Проверка источников: 7 ноября 2026 года. Версия протокола: **2026-07-28**. Прочитанная редакция первоисточника закреплена на commit **cf59bb0d8b43e711420f5f7313aa6cca3f1e1898**. Точные источники, проверенные утверждения и лицензионная оговорка находятся в [sources.json](sources.json).

## Запуск без аккаунта и установки зависимостей

Из этой папки, Node.js 24:

```sh
node --test protocol.test.mjs
node demo.mjs
```

Demo запускает дочерний Node-процесс через stdio. Он показывает discovery, список единственного инструмента, чтение вымышленной заметки и намеренный отказ запросу со старой версией. Последняя строка с -32022 ожидаема. stdout содержит только JSON-RPC; сеть, модель и внешние сервисы не вызываются.

Для ручного обмена можно запустить `node server.mjs` и передавать по одному JSON на строку. Конец stdin закрывает процесс. Параметр пути/команды сервер не принимает.

## Что студент должен увидеть

1. Клиент может начать с tools/list или tools/call. Discovery полезен, но не создаёт сессию и не выдаёт права.
2. Каждый запрос заново передаёт протокольную версию и clientCapabilities. Запрос без них получает -32602, даже после успешного discovery.
3. На несовместимую версию возвращаются -32022, перечень supported и запрошенная версия requested. Это повод выбрать поддерживаемый вариант, а не незаметно переключаться на старый handshake.
4. Успешный и ошибочный результат инструмента имеет resultType: complete. Неизвестный инструмент — протокольная ошибка; недопустимый topic известного инструмента — результат с isError: true.
5. readOnlyHint сообщает намерение сервера, но не создаёт защиту. В этом конкретном коде безопасность обеспечивается тем, что обработчик не имеет инструментов чтения диска, записи, shell или сети; он возвращает только фиксированные строки.
6. clientInfo и serverInfo — самозаявленная информация для диагностики. Она не доказывает личность и не меняет доступ.

### Не путать две версии

В каждом запросе `params._meta['io.modelcontextprotocol/protocolVersion']` задаёт версию **протокола**. В ответе на discovery поле `supportedVersions` перечисляет поддерживаемые протокольные версии. В ошибке -32022 поля `data.requested` и `data.supported` показывают запрошенную и поддерживаемые версии.

Обычные успешные ответы tools/list и tools/call в этом примере не повторяют версию протокола: сопоставляй их с исходным запросом по `id`. Поле `result._meta['io.modelcontextprotocol/serverInfo'].version` равно `0.1.0` и обозначает версию **программы сервера**, а не MCP. Его нельзя сравнивать с `2026-07-28` для выбора протокольной версии.

## Практика и критерии приёмки

- Сопоставь четыре запроса из demo.mjs с четырьмя ответами запуска по id. Найди версию протокола в каждом запросе, supportedVersions в discovery и requested/supported в ошибке. Отметь, в каких успешных ответах протокольная версия не повторяется.
- Отдельно выпиши serverInfo.version и объясни, почему 0.1.0 — версия программы, а не версия MCP.
- Удали clientCapabilities у второго запроса. Объясни отказ и восстанови его, не добавляя initialize.
- Добавь к topic поле command и покажи безопасный отказ. Не расширяй реальные полномочия процесса.
- Придумай третью синтетическую заметку, обнови допустимые значения и свой тест. Покажи diff и зелёные проверки.
- Объясни разницу между протокольной stateless-моделью и состоянием прикладной задачи. Этот сервер не хранит ни того, ни другого.

Преподаватель оценивает фактический JSON-обмен, отрицательные случаи и объяснение границ. Запуск этого примера не подтверждает подключение к реальному AI-клиенту, работу LLM, удалённую интеграцию или production-ready статус.

## Границы и непройденные проверки

- Поддержан только выбранный синхронный read-only subset: discovery, tools/list, tools/call и обработка неизвестных методов. Нет HTTP, OAuth, subscriptions, MRTR, Tasks, динамических ресурсов или асинхронной работы. Уведомления не исполняются как запросы и не получают ответ; длительных in-flight операций для отмены здесь нет.
- Схема инструмента фиксирована, её аргументы проверяются вручную. Нет универсального JSON Schema 2020-12 валидатора, загрузки внешних $ref или поддержки произвольных схем.
- Транспорт ограничивает незавершённый кадр 32768 байтами, проверяет UTF-8 и восстанавливается после неверной строки. Это не полноценная защита от DoS: rate limiting и лимит времени жизни процесса не реализованы в сервере. Demo ограничивает время дочернего процесса тремя секундами.
- В закреплённой спецификации server/tools.mdx раздел Security Considerations требует ограничивать частоту вызовов инструментов (MUST). Здесь это требование не выполнено. Наличие учебных тестов и read-only инструмента не позволяет называть пример полностью conformant MCP-сервером.
- ID принимается строкой или безопасным целым числом JavaScript; это дополнительная граница учебного Node-примера.
- Node-процесс всё ещё имеет обычные права пользователя ОС. Отсутствие опасных инструментов в этом обработчике не является sandbox. Не использовать его как основу запуска недоверенного кода.
- Не запускались официальная conformance suite, совместимость с внешним MCP host/SDK, облачные модели или платные API. Тесты показывают свойства именно этого примера.
- Никакие лицензии чужого курса не перенесены на авторский текст. Корневая лицензия upstream сейчас переходная; не копируйте схему/код/документацию без отдельной проверки указанного LICENSE.
