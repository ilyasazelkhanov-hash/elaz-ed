# Подключить API или CSV

`src/platform/contracts.ts` содержит публичные типы `PlatformApi`, `Data`, `Snapshot`, `ActionReply` и версию API. Используйте существующие server action и права вместо прямой записи таблиц из браузера. Разрешение на интеграцию и её ключи должны принадлежать этой установке.

## Запрос из приложения

Базовый публичный сценарий — POST к `/functions/v1/master-api/v1/dispatch` с JSON:

```json
{
  "auth": "TELEGRAM_INIT_DATA_FROM_CURRENT_SESSION",
  "action": "event.book",
  "payload": { "entityId": "EVENT_ID" }
}
```

`auth` здесь показывает форму, а не действительный ключ. Точные способы передачи Telegram initData/cookie, обязательные заголовки, CORS и CSRF смотрите в текущем серверном обработчике. Успех возвращает `{ snapshot, result? }`, ошибка — серверный ответ с безопасным описанием. Не логируйте initData, cookie и подписи. Не помещайте server role в `auth`.

Цена, баланс, роль, actor и право на награду задаются сервером. Если новый внешний сервис присылает webhook, реализуйте отдельную проверку подписи/секрета, срок, inbox-deduplication, повтор и аудит. Не переиспользуйте Telegram endpoint для произвольного CRM payload. Не считайте наличие поля `INTEGRATION_WEBHOOK_SECRET` готовым коннектором любой CRM.

## CSV: безопасный рабочий процесс

CSV-транспорт реализован в `src/platform/csv.ts`: `parseCsv(text)` возвращает массив строковых записей, `encodeCsv(rows)` — UTF-8 CSV с BOM. Поддерживаются кавычки, запятые, переносы строк и JSON-объекты в экспортируемых ячейках. Ограничения: 2 МБ UTF-8, 10 000 строк данных, 64 столбца, 65 536 символов в ячейке. Некорректные кавычки, дубли/пустые/опасные имена колонок и несовпадение ширины строк дают ошибку.

Это транспорт, а не обход серверной валидации. Согласуйте маппинг полей; преобразуйте числа/boolean явно, а колонку `data` разбирайте через `JSON.parse` с проверкой структуры. Не передавайте произвольные CSV-ключи непосредственно в серверный action. Для каталога используйте разрешённый `admin.entity.save`; для существующего участника — `admin.member.update`. Автоматическое создание произвольных Telegram-аккаунтов из CSV не предусмотрено. Точное наличие UI импорта/экспорта сверяйте с текущей админкой. CSV с участниками хранится вне мастера и не входит в генерацию.

Пример спецификации обмена для каталога, а не команда импорта:

```csv
external_id,kind,module,title,price,currency,published
demo-service-01,service,commerce,"Консультация",15000,KZT,false
```

Согласуйте UTF-8, разделитель, экранирование кавычек, часовой пояс дат, единицы цены и валюту, обязательные поля, максимальные размеры и стабильный `external_id`. Перед импортом проверьте неизвестные kind/module, ссылки на команды/курсы, дубликаты, отрицательные суммы, формулы в ячейках и неоднозначные даты. Сначала сделайте dry-run с номерами ошибочных строк; загрузка должна иметь отчёт и стратегию повторной отправки без дублей.

`encodeCsv` нейтрализует формулы, начинающиеся с `=`, `+`, `-`, `@` с учётом начальных пробелов, а также начальные tab/CR/LF, добавляя апостроф. Это намеренно меняет текст таких ячеек при обратном импорте; поле вроде отрицательной суммы требует доменного разбора и проверки, а не слепого round-trip. Ограничьте поля ролью и назначением выгрузки; не экспортируйте приватные домашние работы и контакты без основания.

## Приёмка коннектора

Проверьте на стенде корректную запись, неверную подпись, повтор, просрочку, неизвестного участника, выключенный модуль, отказ внешней системы и восстановление. Согласуйте retries, rate limit, журнал ошибок и ответственного. До этих проверок интеграция считается подготовленной к подключению, а не работающей.


Общий HMAC endpoint уже реализован: [контракт событий](INTEGRATION-EVENTS.md). CSV-импорт сотрудников создаёт числовые заготовки для предварительного одобрения; реальные имена обновляются после подтверждённого входа Telegram. Это не создание Telegram-аккаунтов.
