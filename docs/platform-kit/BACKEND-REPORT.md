# Реализация серверной части v1

Канонический код — supabase/functions/_shared, entry point — master-api. Server предоставляет portable re-export и owner provisioning. Миграция создаёт только az_*; RLS включён, публичные таблицы и RPC закрыты для anon/authenticated. Actor определяется из Telegram initData либо OIDC session.

Реализованы операции модулей, private entity editor, роли и scopes, серверные квизы/игры, лояльность, транзакционные остатки, бронирование, ожидание, брифы, order request ID, обучение и сертификаты, сообщество, HR, Stars/возвраты, аналитика, уведомления и подписанный integration inbox. Детали — server/README.md, CAPABILITIES.md и INTEGRATION-EVENTS.md.

Наставник с teamId ограничен работами и файлами команды; наставник без команды имеет общий охват. Кассир ограничен точками купонов/мероприятий; data.pointId товара ограничивает просмотр и управление заказом. Товар без точки общий. Владелец/администратор имеют глобальный административный охват.

В snapshot нет ключей квиза даже для владельца: редактор получает их через разрешённый admin.entity.get. Повторное открытие продолжает попытку. Client score игры не определяет ценный выигрыш. Для призов настраиваются подтверждённые завершения кампании и окно получения.

Уведомления: приветствие, событие, неактивность и задание в день открытия. Последний вариант включается notifications.taskRemindersEnabled; пример — server/rules.example.json. Очередь учитывает тихие часы, отписку, retry, lease и устаревшие задания. Доставка бота — at least once: сбой после принятия Telegram и до подтверждения БД может повторить сообщение.

Проверки разделены на unit/HTTP, SQL в PGlite, native PostgreSQL с несколькими соединениями, миграции прежнего OG и браузер. Актуальные результаты — VERIFICATION.md. Реальных Telegram/Storage/Stars операций, облачных миграций, деплоя и рассылок в этой работе не выполнялось.
