# Воспроизводимые проверки

CI использует Windows, Node 24.19.0, Python 3.12.10 и FFmpeg/ffprobe 8.1.2 (Gyan essentials, SHA256 проверяется до распаковки). Для Python выбран выпуск с готовой Windows-сборкой setup-python; локально проверено на bundled Python 3.12.14. Python-проверки используют стандартную библиотеку; matplotlib для них не нужен. Локально допустим Node 24, Python 3.12+ и FFmpeg с ffprobe в PATH. Полные версии сохраняются в отчёте проверки.

Установить зависимости через `npm ci`, добавить каталог FFmpeg bin в PATH. Если команда Python отличается от стандартной, задать переменную `PYTHON` абсолютным путём к исполняемому файлу.

Запуск: `npm run test:all`. Предварительная проверка объяснит отсутствие Python/FFmpeg. Скрипт копирует проект во временную папку, использует установленные node_modules, запускает все объявленные test:* (кроме самого test:all и отдельной браузерной проверки), затем сборку. Учебные материалы генерируются только в этой копии. Логи и JSON-итог находятся в игнорируемой папке test-results; временная папка указана в отчёте и сохраняется для расследования.

Тестовые файлы выполняются последовательно: это предотвращает перегрузку WASM PostgreSQL и таймауты дочерних процессов на Windows. Проверки защиты от символьных ссылок используют файловые ссылки в Linux и каталоги junction в Windows; пропуска проверок нет, права администратора Windows не требуются.

Отдельная проверка нескольких assessment: `npm run test:multiple-assessments`. Новые регрессии платежей и достижений: `npm run test:audit-remediation`. Браузерная проверка использует scripts/ui-accessibility-browser.cjs с Playwright и запущенным Vite; её результаты фиксируются отдельно от unit/SQL.

Workflow обязателен в коде для push main и pull_request; включение required status check в настройках защиты ветки GitHub выполняется владельцем репозитория отдельно. Само наличие workflow не изменяет настройки защиты ветки.
