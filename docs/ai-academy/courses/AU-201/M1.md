## AU-201-M1-L1 · HTTP-запрос как договор

HTTP-запрос состоит из метода, адреса, заголовков и при необходимости тела. GET читает представление, POST обычно создаёт или запускает действие, но окончательный смысл задаёт контракт конкретного API. Заголовок Authorization несёт данные аутентификации, а Content-Type описывает формат тела. Перенос токена в текст обращения смешивает служебные данные с пользовательскими.

В лаборатории /tickets выдаёт страницы вымышленных обращений. Сервер принимает только учебное значение Bearer training-only. Это имитация проверки заголовка, а не защита рабочего сервиса. Вызов /run выполняет запросы только к тому же локальному процессу.

Сравни код HTTP и содержимое JSON. Ошибка может прийти без ожидаемых полей, поэтому сначала проверяется статус, затем структура ответа. Наличие поля ok не заменяет проверку статуса. Нарисуй один запрос по слоям и объясни, какие части меняются при выборе другой страницы. Не используй реальные токены в снимках экрана. Для каждого заголовка запиши назначение, а не только строку из готового примера.

### Практика

Результат: Размеченный HTTP-запрос и контракт ответа. Сначала запиши ожидание для одного входа. Затем выполни локальный сценарий и сопоставь статус, данные и число попыток. Сохрани точную команду или выбор сценария и фактический результат; не отмечай неисполненный шаг как успешный.

### Самопроверка

- Метод, путь, заголовки и тело различены
- Учебный токен не назван рабочей защитой
- Статус проверяется до структуры результата

## AU-201-M1-L2 · События, OAuth и страницы выдачи

Webhook доставляет событие от отправителя получателю; запрос страницы читает состояние по инициативе клиента. Эти механизмы не взаимозаменяемы. При повторной доставке webhook нужен устойчивый ID события, а при чтении нескольких страниц — правило перехода nextPage и защита от цикла.

OAuth описывает делегированный доступ. В распространённом кодовом потоке пользователь подтверждает разрешения у поставщика, приложение получает код и обменивает его на ограниченный доступ по правилам поставщика. Это не передача пароля пользователя твоему workflow. Для реального подключения нужны зарегистрированное приложение, разрешённый redirect и поддерживаемые параметры; лаборатория не выдаёт настоящие OAuth-токены.

В /tickets сначала приходит страница 1, затем 2, затем nextPage=null. Нельзя считать первую страницу полным каталогом. Если поставщик возвращает непрозрачный cursor, не придумывай номер следующей страницы самостоятельно. Составь две схемы: путь события и путь чтения страниц. Отдельно укажи, где проверяется право доступа и когда требуется его обновление. Отсутствующие разрешения нельзя исправить повторением того же запроса бесконечно.

### Практика

## AU-201-M1-L4 · 401, 429, 500 и таймаут

Коды ошибок подсказывают класс проблемы, но не заменяют документацию поставщика. 401 в лаборатории означает неверный учебный заголовок. Его не повторяют автоматически: нужны корректные условия входа. 429 означает ограничение частоты; Retry-After задаёт минимальное ожидание в демонстрируемом контракте. 500 моделирует временный сбой, для которого допускается ограниченный повтор чтения.

Таймаут означает отсутствие ответа в установленное время, а не доказанное отсутствие выполненного действия. Для изменяющих запросов это критично: повтор без устойчивого ключа может создать второй объект. В лаборатории автоматически повторяются только безопасные учебные чтения.

Выполни четыре сценария и сравни attempts. Для 401 будет одна попытка; для 429 и 500 успех наступает на третьей; таймаут прекращается после лимита. LogicalWaitsMs показывает расчёт задержек без настоящего ожидания. Не выдавай эту ускоренную демонстрацию за измерение производительности сети. Запиши, какое изменение исправит причину каждого сбоя и какой повтор допустим только после проверки результата предыдущей операции.

Результат: Матрица четырёх отказов и правил повтора. Сначала запиши ожидание для одного входа. Затем выполни локальный сценарий и сопоставь статус, данные и число попыток. Сохрани точную команду или выбор сценария и фактический результат; не отмечай неисполненный шаг как успешный.
