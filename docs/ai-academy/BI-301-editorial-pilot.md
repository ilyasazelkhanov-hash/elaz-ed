# BI-301: пилот соответствия урока и практики

Локальная редактура по разделам 7–8 отчёта OG CRE8R от 11 ноября 2026 года. Это не публикация в Supabase, не независимое ревью и не подтверждение результатов учеников. Другие 27 курсов не проходили эту редактуру. Решение о публикации и педагогическая приёмка остаются отдельными этапами.

## Что изменено

- Вместо четырёх повторяемых модульных примеров BI-301 получает 16 разборов по действию конкретного урока.
- Для каждого разбора есть отдельные исходные данные, три объяснённых шага, результат, ошибка и проверка, затем попытка на изменённых данных, две подсказки и перенос в новый контекст.
- В конце каждого модуля дана контрольная практика; последняя объединяет итоговый проект с новой задачей без готового решения.
- Авторские основные блоки, названия, артефакты, acceptance, assessment и итоговая рубрика сохранены. Отметки самопроверки не заменяют существующее оценивание. Независимый проверяющий и сроки проверки не обещаются.
- Режимы «локальный запуск», «AI-запуск» и «анализ готового примера» различаются явно. Все новые случаи синтетические.
- Несоответствующая схема расчёта портфеля больше не иллюстрирует первый урок аудита. Общие модульные схемы других курсов сохранены.

## Источники и воспроизводимость

Источник новых случаев: `content/ai-academy/lesson-examples/BI-301.json`. Это авторские учебные сценарии, а не новые факты о реальных поставщиках. Существующие внешние ссылки курса не менялись и заново не проверялись.

Мини-наборы модуля 1 отделены от исполняемого `business-lab/portfolio.json`. В уроке 4.3 используются именно числа лаборатории. TCO в 3.2 рассчитан из явно перечисленных допущений; цена не считается разрешением закупки или доказанной экономией.

```sh
npm run academy:enrich -- --course=BI-301
npm run academy:content
node --experimental-transform-types --no-warnings --test tests/academy-enrichment.test.mjs
npm run test:academy
npm run build
```

`academy:content` отклоняет устаревшие сгенерированные примеры. Проверяются полное покрытие уроков, уникальность ID, исходных данных, результатов, попыток, переносов и шагов, а также точное совпадение названия, артефакта и критериев с авторским уроком. Смысловую правильность эти структурные проверки не доказывают.

Генерация сохраняет совместимый с текущим LessonStudy тип `module_example`, но помечает источник как `example_scope: lesson` и указывает `source_lesson_code`. Практика остаётся отдельным Markdown-блоком и отображается в разделах практики, подсказок и проверки. Несоответствующая модульная диаграмма не прикрепляется к индивидуальному примеру.

Общая ревизия каталога обновляет поле revision всех публичных файлов материалов; содержание остальных 27 пакетов не меняется. Генератор книг также может обнаружить прежние несинхронные изображения других курсов. Эти посторонние изменения не относятся к данному пилоту.

## Перед публикацией

Редактору нужно пройти все 16 связок «результат → пример → попытка → критерии», особенно интерпретацию свидетельств 1.1, ограничения часов 1.4, границы допуска 2.1, TCO и тип затрат 3.2, перенос в 4.4. Затем проверить одну настоящую работу по каждому модулю и согласованность оценивания между проверяющими.

Длительности из каталога сохранены, но не измерялись на учениках. Нужны наблюдаемые прохождения, проверка нагрузки чтения и практики и решение о ресурсах проверки. Автотесты, чтение материалов и самопроверка не являются доказательством освоения навыка.
