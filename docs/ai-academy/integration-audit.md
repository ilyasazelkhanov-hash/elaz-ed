# AI Academy — интеграционный аудит

Дата: 18 октября 2026. Задание: внедрение предоставленных Markdown/JSON внутрь действующего OG, без замены приложения.

## Существующая система

- React 19, TypeScript, Vite, Tailwind 4, Motion, Zustand. Темы и типографика OG заданы в `src/index.css`, общие интерактивные элементы — `src/ui.tsx`.
- Три основные вкладки и стек экранов в `src/App.tsx`/`src/store.ts`. Для академии добавляется лениво загружаемый экран. Внутренние URL академии сохраняются в hash, поддерживаются стартовые `/academy/...` и `#/academy/...`. Старые ссылки уроков и курсов остаются прежними.
- Настоящий API — `supabase/functions/api/index.ts`, проверяющий подпись Telegram, срок initData, пользователя и членство в канале. Участник академии проходит тот же `member(body)`. Право администратора нельзя получать из тела запроса.
- Существующие `courses`, `lessons`, `progress`, `users`, Stars, квизы и адвент используются действующим OG. Клубное пространство — отдельная переносимая подсистема. Их данные не перемещаются и не заменяются новым seed.
- Локальный деморежим отделён от серверного API и хранит данные в localStorage. Для академии используется отдельный ключ `og:academy:demo:v1`, интерфейс помечен «ДЕМО».
- Проверки API используют Node 24 и поддельные HTTP/Telegram ответы. PGlite позволяет проверить настоящую PostgreSQL-семантику миграций без облачного проекта.

## Решения

1. Добавить аддитивную подсистему `aa_*`, привязанную к существующему `users.id` (Telegram bigint). Не менять ID и прогресс старых уроков. Внутри нового каталога использовать стабильные строковые коды из JSON.
2. Направления, курсы, модули, занятия, источники, навыки, assessments и рубрики хранятся в типизированном дереве `aa_nodes`. FK parent_code и серверные проверки сохраняют структуру. Это адаптация логической схемы из ТЗ, а не переписывание старых сущностей.
3. Зачисления, прогресс, попытки, работы, отзывы, placements, сертификаты, роли и аудит — отдельные связанные таблицы. Составные блоки — JSON внутри версионируемого занятия; старые снимки оценивания сохраняются в попытках/работах.
4. Единственный транспортный маршрут `/academy` в существующей Edge Function вызывает `academy_action`. Таблицы и RPC закрыты от anon/authenticated, service_role доступен только серверу. Проверка действий и видимости выполняется в SQL, UI не является границей защиты.
5. Исходные документы скопированы в `content/ai-academy/reference`, нормализованный импорт — `catalog.normalized.json`. Все учебные сущности initially outline; source links internal, источники reference_only/unchecked. Авторские материалы должны быть подготовлены и утверждены до публикации.
6. Публичные карточки показывают программу, а учебные тела/проверки доступны после серверной проверки доступа. Наличие карточки не означает готовность курса. Для outline предусмотрен лист ожидания.
7. Академия не начисляет новые XP за просмотр планов и не меняет согласованную отдельно экономику OG. Новый платёжный контур, автоматическая проверка ИИ и файловые загрузки не выдумываются. Для практики доступны текст и HTTPS-ссылка; платные доступы требуют явной интеграции с действующим продуктом.

## План и контроль выполнения

Исходная спецификация: `content/ai-academy/reference/AI_Academy_Codex_Implementation_TZ_2026.md`.

- Этап 0: аудит — этот документ.
- Этап 1: схема, валидатор, нормализация, dry-run, идемпотентный импорт.
- Этап 2: каталог, направление, курс, библиотека, поиск и фильтры.
- Этап 3: контентные блоки, зачисление, прогресс, тесты, версии практики и оценивание.
- Этап 4: редактирование, упорядочивание, источники, роли и журнал.
- Этап 5: SQL, API, сборка и браузерные проверки; факты и ограничения записываются в implementation-report.md.

Работа ведётся в текущем checkout с существующими незакоммиченными изменениями, поскольку пользователь просит интеграцию в уже открытый локальный OG. Эти изменения сохраняются. Миграции не применяются к облаку, сообщения и оплаты не отправляются, релиз не выполняется автоматически.
