# Private assignment files and consentful portfolio

Apply `20261018170000_ai_academy_files.sql` after the base Academy migration. In Supabase it creates or hardens `academy-private` as a private bucket with a 10 MiB object limit and an explicit MIME allowlist. In local PostgreSQL without Storage tables it still installs the domain functions. The API reports `academy_storage_unavailable` when Storage or bucket configuration is unavailable; it never reports a fake upload success. No cloud migrations or uploads are performed by the local tests.

The verified `/academy` member route delegates `file_upload`, `file_finalize`, and `file_download` to `handleAcademyFiles`. The existing service client is injected; no additional credentials are accepted from the browser. `file_upload` takes `{lesson_code,filename,mime,size}` and returns `{file_id,path,token,signed_url}`. A reservation belongs to the authenticated actor and to one lesson (including its child assessments), or to one course capstone. Its path is `actorID/randomUUID.extension`, independent of client paths. Reservations are limited to 100 per actor per hour. Use up to 10 ready file IDs in submission artifact `file_ids`.

The browser performs a real multipart `PUT` to the returned signed upload URL, with `cacheControl`, a Blob of the declared MIME, and `x-upsert: false`. This follows [Supabase uploadToSignedUrl](https://supabase.com/docs/reference/javascript/storage-from-uploadtosignedurl) and its [official implementation](https://github.com/supabase/storage-js/blob/main/src/packages/StorageFileApi.ts). Its success must be followed by `file_finalize {file_id}`. The server independently lists the stored object, checks actual Storage MIME and size against the reservation, downloads the bytes, verifies size and a format signature (or UTF-8 text without active markup), and only then marks the file ready. Client-provided finalize metadata is ignored. Files are immutable: signed upload URLs are issued without upsert and no public Storage write policies are added.

PDF, PNG, JPEG, WEBP, UTF-8 TXT, and ZIP are allowed. HTML, SVG, executable extensions, zero-byte objects, and files larger than 10 MiB are rejected. Signatures are format checks, not malware scanning; PDF and archive contents are not interpreted, unpacked, or executed. Every download is an attachment through a 60-second signed URL. Access is restricted to the owner, a database-configured administrator, or a database-role instructor assigned to a submission containing that file. A caller's `is_admin` or `owner_id` payload cannot grant access.

The submission-save API must call `aa_valid_files(actor,assessment_code,artifact)`. The helper returns false for pending, foreign, duplicate, malformed, or differently scoped IDs. Absence of `file_ids` and an empty array are accepted. It is also appropriate to call it when submitting a saved draft. The helper and all file RPCs are executable only by `service_role`; tables have RLS and no anon/authenticated access.

`AcademyFiles` exports a real upload control with `lessonCode`, `onChange(fileIds)`, and optional `initialFileIds`. Pass the resulting IDs in the assignment artifact. Removing an item detaches it from the form; retained objects are not silently deleted from historical submissions. Pending or unattached object cleanup requires a separate retention policy and is not enabled here.

## Portfolio consent

Authenticated commands are `portfolio_list`, `portfolio_publish {submission_id,consent:true}`, and `portfolio_revoke {submission_id}`. Publication requires the actor's own passed submission and an explicit boolean consent. Only a fresh allowlisted snapshot of artifact `text` (at most 10,000 characters) and a plain public HTTPS `url` is stored. User IDs, instructor notes, rubric/private metadata, and attachment IDs/URLs are excluded. Empty text/link artifacts cannot publish. URLs with credentials, any query, or a fragment are omitted from the public snapshot: these may contain signed or encoded access tokens. Supply a plain permanent URL for public project links; the original private submission is unchanged.

`portfolio_public {slug}` uses `academy_portfolio(null,'public',payload)` and returns only `{slug,title,artifact,published_at}`. Slugs use random UUID entropy. Revocation takes effect for subsequent lookups immediately, and a submission that no longer has a passed state also stops appearing. Previously seen text and links cannot be recalled from readers. Private attachments are never part of public portfolios; publish a suitable external result link if desired.

## Public certificate lookup

`certificate_public {code}` calls `academy_certificate_public(code)` through the API's service client. It returns `{code,course_title,issued_at,valid}`, including false validity for a revoked certificate. Unknown codes return `academy_certificate_not_found`. It exposes no learner name, user ID, private feedback, or other personal fields. Both public lookup RPCs remain revoked from `anon` and `authenticated`; only the API may forward their allowlisted output.

## Local verification

Run `node --experimental-strip-types --test tests/api/academy-files.test.mjs`. Mocked Storage tests check actor binding, real signed URL arguments, invalid MIME/size/path rejection, actual metadata and byte validation, missing objects, and attachment download expiry. PGlite tests install the real migration and exercise file scope/ownership, pending state, assigned instructor access, consent, revocation, public field privacy, certificate privacy, and anonymous privilege denial. They make no provider writes.
