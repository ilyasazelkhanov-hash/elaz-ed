# OG: маршрут, профиль, клуб и услуги

Главная сохраняет три вкладки. «Мой следующий шаг» открывает цель и до четырёх доступных материалов. Непубличные материалы и закрытые уроки курса без пробного доступа не попадают в маршрут. Завершение отмечается только прежним сервером уроков. Цель хранится в клубном профиле (`journey.choose`), а локальная копия нужна для отображения на устройстве. До подключения клуба доступна локальная настройка цели.

Профиль открывает клуб и примеры услуг. Пять отраслевых демонстраций явно используют демо-адаптер и отдельные идентификаторы `og-showcase-*`; их покупки и заявки не отправляются автору и не меняют боевые данные.

## Доступ и подписка

Клубный план — сущность `course` с `data.subscription=true`. Стоимость и наполнение задаёт автор в каталоге. Пример `club-membership` и его цена демонстрационные; перед публикацией замените их реальным предложением. Регулярное продление — каждые 30 дней через Telegram Stars. В браузере реальная оплата недоступна. Доступ выдаётся сервером по подтверждённому платежу, а состояние окна оплаты используется только для обновления экрана. Возвраты обрабатываются по конкретному платежу периода.

Заявки на разработку сохраняются через `order.create` для бесплатной сущности `service-miniapp-brief` с `data.purpose='miniapp-brief'`. Контакт и задача записываются в заказ; сетевой повтор использует прежний UUID. Платная консультация из другого раздела не подставляется автоматически. Без сервера и опубликованного брифа кнопка отправки недоступна.

## Общий прогресс

База OG (`users.xp`) и клуб (`az_members.xp`) сохраняют собственные журналы. Приватные RPC `az_og_progress_summary` и `az_og_progress_top` строят общую сводку и рейтинг. Старые пользователи, ещё не открывавшие клуб, имеют нулевую клубную часть и продолжают входить в OG. Начисления не копируются между базовыми таблицами и не суммируются повторно при перезагрузке.

Обычный OG использует модули content, progress, learning, events, retention и commerce. Навигация клубного пространства — главная, обучение, профиль. Полный набор доступен в отдельных отраслевых демонстрациях; исходники остальных модулей остаются в переносимой копии.

## Выпуск

1. Сохраните backup и примените на стенде все четыре новые миграции `20261018*.sql` по порядку после прежних миграций: expansion, expansion_review, refund_retry и early_access.
2. Разверните оригинальную `api` и `az-master-api`. Оставьте единственный webhook OG на оригинальной `api/webhook`.
3. Передайте в provisioning конфигурацию OG с `id=og-cre8r` и сокращёнными модулями. `src/lib/og-config.ts` описывает тот же состав на клиенте.
4. Проверьте старого и нового участника, оплату, продление, отмену автопродления в Telegram, возврат конкретного периода, истечение доступа, повтор webhook и заявку.
5. После проверки включите серверный `OG_PLATFORM_ENABLED=true` в оригинальной API и фронтенд `VITE_PLATFORM_ENABLED=true`. Адрес клубного API — `VITE_PLATFORM_API_URL=/platform-api`. Секреты остаются только на сервере.

Локальные проверки не подтверждают работу настоящего бота, биллинга или развёрнутого окружения. Во время этой реализации облачные миграции, сообщения и оплаты не выполняются.

## Проверки

`npm run test:experience`, `npm run test:api`, `npm run test:database`, `npm run build`. Мобильные сценарии и ограничения фиксируются в отчёте текущей поставки. OG не импортирует соседнюю папку Azelkhanov-master.

Переход из маршрута: при запущенном OG выполните `node Azelkhanov-master/tests/og-journey-browser.mjs` из общей папки. При необходимости задайте `OG_URL` и `AZ_CHROME_PATH`. QA-скрипт использует установленный Playwright мастера; работа и сборка OG от него не зависят. Проверяются открытие и доступность урока поверх маршрута на 390/1280 px, возврат назад и HTTP-клиент с уникальным ID материала в тестовом ответе API. Боевая база в этой проверке не используется. Экраны маршрута и урока имеют одинаковый базовый слой: более поздний экран в стеке открывается поверх предыдущего.
