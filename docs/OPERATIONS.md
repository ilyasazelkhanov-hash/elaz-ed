# Выпуск и обслуживание OG CRE8R

Дорожная карта хранит решения, состояние и квитанции. Эта инструкция описывает повторяемые действия для OG. Academy, Platform Kit и Azelkhanov Master проверяются как самостоятельные системы.

## Разработка и GitHub

- В отдельной рабочей копии от свежего origin/main: Node 24.19.0, Python 3.12+, FFmpeg и FFprobe. Установить зависимости командой `npm ci`. Для локального предпросмотра `npm run dev` и `/?demo`.
- Перед PR выполнить `npm run test:all`. Затем `npx playwright install chromium` и `node scripts/og-product-browser.mjs`, который читает путь готовой сборки из audit-validation.json. Для сравнения объёма ресурсов использовать `node scripts/perf-assets.mjs --dist <dist> --include App`. HTTP-трафик и отзывчивость измерять отдельно в браузере на одном мобильном профиле.
- Слияние через PR. Для main нужны verify, Master platform and client templates, Edge API and release tools и Edge API typecheck. Внешние обновления зависимостей проходят те же проверки. Выводы CI содержат только синтетические данные. Перед закрытием репозитория проверить тариф, обязательные проверки и интеграцию Vercel.

## Публикация и откат

1. Сохранить предыдущий успешный SHA Vercel, версию Edge и журнал применённых миграций. Проверить, что preview и production используют правильные окружения. Для браузера разрешён только публичный `VITE_API_URL`. Значения серверных секретов остаются в Supabase.
2. После слияния дождаться target SHA на Vercel. `/release.json` показывает SHA сборки, fingerprint и состояние отслеживаемых файлов. `/runtime.json` публикует адрес API из той же настройки Vite, что и клиент. При dirty:true изучить build logs с `Frontend source diagnostics`, сравнить объявленный и фактический SHA и список изменённых путей. Повторить чистый build после устранения причины.
3. Выполнить `npm run release:smoke` с `RELEASE_EXPECTED_COMMIT`, `RELEASE_APP_URL` и `RELEASE_API_URL`. Live OG checks выполняет ту же проверку при событии успешной выкладки и раз в сутки. Задание не вызывает оплату, админские изменения или Telegram-рассылку. Проверить фактический запуск от Vercel после первого слияния.
4. Frontend выкладывается через Vercel. Edge и миграции выпускать по отдельному манифесту с зависимостями по проекту. Сначала сверить применённые версии, прогнать точный пакет на изолированной базе, определить обратную совместимость, подтвердить восстановление. Исторические SQL-импорты учебных путей меняют настройки курсов. Для редакционной правки применять адресное изменение тела проверенного урока с проверкой исходного хеша. Не создавать квитанцию версии по совпадению названий.
5. При проблеме фронтенда использовать совместимый предыдущий деплой или revert через PR. По данным предпочесть исправляющую миграцию, сохранив покупки и доступы. Для старых клиентов вызов физического удаления материала после выкладки Edge возвращает 409.

## Контент и восстановление

- [Создание новостей](NEWS-AUTOMATION.md) каждые три дня. [Доставка](NEWS-PUBLISHING.md) выполняется действующим воркером. Публикация в приложении и факт отправки в Telegram проверяются независимо. Ошибка или остановка очереди требует сверки по журналу; unknown нельзя считать доставленным.
- Один редакционный обзор каждые пять дней предлагает правки с первоисточниками. Не менять акцию или тариф автоматически. Новые полные тексты платных уроков вести в закрытом рабочем хранилище. Для проверок издателя установить пути к обеим частям авторского корпуса по NEWS-AUTOMATION.md.
- В защищённой среде сохранить актуальную резервную копию БД и байты объектов Storage. Восстановить копию в изолированный Postgres/Supabase с отключёнными cron, вебхуками и внешними ключами. Сверить записи доступа, уроки, прогресс, оплаты и байты файлов командой `node scripts/verify-recovery.mjs <original.json> <restored.json>`. Отдельно проверить вход с тестовыми ролями, возможность чтения платного урока, права и очереди. Записать время восстановления и окно потери данных без публикации снимков.
- Реальный Telegram на iOS/Android проверяется отдельно от Chromium. Приёмка подписчика включает вход из новости по ссылке, просмотр бесплатной практики, Back/Close и проверку экрана с клавиатурой. Покупку и возврат сначала принимать на тестовых данных.

Владелец проверяет раз в неделю попытки первого задания за 7 дней, возврат на второй неделе и путь к оплаченной покупке. Показывать знаменатели и исключать демо. Для следующего изменения сопоставить цифры с пятью наблюдениями за новичками и выбрать одну проблему.
