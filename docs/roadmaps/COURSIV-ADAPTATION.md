Версия плана: 1.1. Дата: 2026-11-12. Проверенный исходный снимок: `cd09c91a9709f8988cf825077a4afd9d1c61d523`.

Это план реализации с проверяемыми критериями, а не перечень обещаний. Исследование: «Coursiv и развитие OG CRE8R», 17 страниц, переданные владельцу DOCX/PDF. Платная сессия Coursiv не тестировалась. Официальные промоскриншоты не доказывают фактическую реализацию всех функций. Оценки, жалобы и маркетинговые заявления не являются доказательством учебной эффективности.

## Правила ведения

- `source-present`: функция найдена в исходниках, это не подтверждение развёрнутого backend или результата в реальном аккаунте.
- `partial`: часть сценария существует; указан конкретный пробел.
- `in-progress`: работа назначена, но ещё не принята и не опубликована.
- `planned`: критерии определены, работа не начата в этом плане.
- `deployment-check`: нужен отдельный разрешённый smoke или проверка миграций/сервера.
- `deferred`: отдельный эксперимент или инфраструктурное решение, не текущий выпуск.
- `verified-live` разрешён только с commit, датой, средой, шагами проверки и оговорками. Срез 31a2b67 ниже имеет подтверждённую frontend-публикацию, но это не подтверждение всего пункта или backend.

При каждом выпуске обновлять конкретные строки, не переписывать исходный baseline. Хранить ссылку на тест и проверку реального сценария. Новая версия UI не означает автоматический выпуск миграций, контента или прав доступа. План не даёт разрешения удалять данные, покупать сервисы, расширять полномочия, публиковать работы учащихся или отправлять им сообщения.

## Последовательность без параллельных систем

1. Сохранить этот baseline, вести C01 и C07 отдельными workstream с общей проверкой UX. Не объявлять работу завершённой до тестов и интеграции.
2. Проверить существующие C04/C05/C18. Наличие server code не доказывает миграции. Не тратить деньги и не удалять записи в smoke.
3. Принять один вертикальный сценарий: выбрать цель -> увидеть следующий доступный шаг -> выполнить практику -> сохранить/экспортировать -> понять статус результата -> продолжить.
4. Подключить существующие placement/rubric/portfolio, если они реально доступны. При недоступном сервере явно показать локальную практику и её пределы, не скрыто подменять backend.
5. Расширять авторскую переработку по курсам после пилота; перечислять обновлённые коды и проверенные критерии, не писать «все курсы улучшены».
6. Затем запускать измерение переноса навыка, повторение и новые среды. Не копировать подписной funnel Coursiv ради конверсии без прозрачных условий.

## Текущий срез, согласованный между исполнителями

Этот scope реализован в frontend 31a2b67. Границы проверки ниже; не весь отчёт Coursiv завершён:

- `learning_path`: LearningNext на главной, после Dots/daily/advent в сохранённом порядке пользователя; объяснение следующего действия; scoped preference/последний бесплатный шаг; платное продолжение только по серверным completion/access. Возможная короткая самопроверка опытного не является официальной аттестацией или снятием lock. Области реализации: Home, LearningNext, learning-next, FreeStart и OGPractice.
- `practice_learning`: FreeStart/PracticeReader, локальный артефакт, критерии из существующих guides, явное сохранение/экспорт в браузере; recovery несохранённой работы в ограниченной JS memory проверено на SPA-переходах, но не сохраняет её после reload. Нет независимой оценки, серверной синхронизации, начисления XP или сертификата. Это срез C07, не завершение C03/C11/C12.
- `research_plan_og`: только этот документ. Runtime, API, БД, роли и CI не меняются.

Характер хранилища после интеграции подтверждён: baseline использует sessionStorage, новый срез использует scoped localStorage. Ни тот, ни другой вариант не должен называться cross-device синхронизацией. Показать пользователю реальное ограничение хранения работы.

## Критические границы доступа

- Обычные изменения кода и UI относятся к поручению владельца; публикация производится координирующим исполнителем после проверки exact SHA и применимого подтверждения.
- Миграции меняющие продакшен и доступ к данным требуют отдельной оценки совместимости, backup и rollback. Не удалять данные в рамках этой дорожной карты.
- Постоянный перенос черновиков на сервер меняет хранение пользовательского ввода. Нужны минимизация данных, RLS, срок хранения и видимое объяснение, особенно для медицинских примеров.
- Платный LLM, новая подписка, карты/платежи, расширение прав сервиса и добавление новых внешних получателей не следуют автоматически из «внедрить исследование».
- Публикация работ учащихся только по их отдельному согласию. Зачёт/сертификат только по существующим проверенным правилам, а не за нажатие CTA.

## Чек-лист приёмки каждого среза

- [ ] Указаны commit, baseline, изменённые файлы и IDs плана.
- [ ] Нет обхода access/enrollment/assessment на клиенте.
- [ ] Проверены guest/new/continuing/completed/inaccessible/error/timeout и смена пользователя.
- [ ] Черновик, работа и зачёт имеют честно разные состояния.
- [ ] Фокус, возврат, повторное нажатие, длинный текст, 320/390 и reduced motion проверены с оговорками.
- [ ] Unit/integration и итоговый `npm run test:all` пройдены на exact integration SHA. Записаны не запущенные тесты.
- [ ] GitHub SHA, CI, Vercel и backend/migrations имеют отдельные статусы.
- [ ] Проверен реальный аккаунт или прямо указано, что был только demo.
- [ ] Документ/контент/БД изменения перечислены отдельно, rollback не уничтожает данные.

## Измерение пилота

Минимальные показатели: время до первого сохранённого результата; доля работ с выполненной рубрикой; выполнение нового аналогичного задания без подсказки; восстановление незавершённой работы; неопределённые оплаты/повторы; трудности на телефоне и с клавиатуры. Для каждого сохранять знаменатель, окно времени и тип аудитории. Не использовать общий XP как метрику обучения. До определения privacy-safe схемы и baseline это план измерения, не существующий dashboard.

## Следующие три независимых среза

Статус всех трёх: **planned**, это задания для исполнителей, не утверждение о выполнении. Выбраны только локальные изменения без новых провайдеров, услуг, автоматических сообщений, серверного хранения работ или миграций. Платёжный и recovery gate остаются приоритетными открытыми рисками, но не обходятся этим frontend-пакетом.

### S1. Найти свою сохранённую работу в профиле (C11/C12, ограниченный локальный срез)

**Проблема в 31a2b67:** работа сохраняется явно, но вернуться к ней можно только вспомнив урок. `Profile.tsx` не показывает сохранённые practice artifacts. Существующее Academy portfolio нельзя смешивать с ними.

**Задание:** добавить компактный раздел «Мои работы в этом браузере». Показывать только результаты, сохранённые кнопкой текущего пользователя/режима, с названием и честным статусом «Черновик»/«Самопроверка». Открывать исходную практику. Для начала достаточно пяти известных бесплатных guides, без сканирования чужих storage keys и без платных материалов. Не публиковать работу и не добавлять XP/skill badge. Пустое состояние объясняет один путь к практике, не создаёт большую карточку на главной.

**Файлы:** новый `src/lib/local-practice-library.ts` (чтение только allowlist `beginnerGuides`, `artifactKey`/`readArtifact`), новый `src/screens/profile/LocalPracticeWorks.tsx`, минимальный вызов в `src/screens/Profile.tsx`; тесты `tests/local-practice-library.test.mjs`. Не менять `practice-artifact.ts` без согласования со S2; для первого среза не нужны новые fields/version миграции storage.

**Приёмка:** saved free artifact появляется и открывает тот же guide; unsaved memory не выдаётся за сохранённую работу; другой account/demo не видит записи; broken/unavailable storage не приводит к ложному empty-success; длинный заголовок и оба типа состояния читаемы 320/390. Не отображать содержимое работы в аналитике. Deleted artifact исчезает после повторного чтения. Paid/Academy portfolio не трогать.

### S2. Конкретная помощь после попытки, не общий список галочек (C09/C10)

**Проблема в 31a2b67:** `artifactFeedback` определяет наличие полей/отметок, но не оценивает смысл и часто возвращает шаблонные фразы. Это честно, но мало обучает.

**Задание:** авторский пилот на `first-request` и `check-answer`: слабый/улучшенный пример, короткое объяснение различия, по одному намёку для результата/проверки/исправления, собственная попытка и новая вводная для повторения без готового ответа. Помощь выдаётся по явному действию рядом с попыткой, не модальным блоком на главной. Указывать, что содержание ответа не оценено автоматически. Сохранять reset критериев при редактировании; не делать fake grade и не раскрывать платный контент.

**Файлы:** новый `src/lib/practice-guidance.ts` с authored hints по ID, новый компактный компонент помощи в `src/screens/home/`; минимальное подключение `FreeStart.tsx`/`PracticeArtifact.tsx`; тесты `tests/practice-guidance.test.mjs` и существующие artifact regression. Не менять Profile и storage format, чтобы S1 был независим. Не добавлять LLM вызовы или отправку текста пользователя.

**Приёмка:** два сценария содержат разные, предметные примеры; empty/partial/self-checked показывают подходящий следующий шаг, но не «ответ правильный»; после правки отмеченные критерии сбрасываются; изменение урока не переносит подсказку/попытку другого guide; повтор задачи не выдаёт XP/сертификат. Проверить кнопку помощи, закрытие/Back, reduced motion и 320/390. Эта задача расширяет помощь, но не закрывает полноценную интеграцию Dots с server review.

### S3. Убрать два препятствия доступу к учёбе (C17 + R6)

**Проблема в 31a2b67:** `src/lib/tg.ts` глобально вызывает `lockOrientation`; `src/screens/academy/Catalog.tsx` отправляет учащегося по «Читать модули» в private GitHub.

**Задание:** убрать автоматическую блокировку ориентации из общей инициализации, не меняя платежи, auth и связанные разрешения. Удалить/заменить ученическую private GitHub CTA на существующий доступный путь курса внутри приложения; не публиковать содержимое репозитория ради починки ссылки и не обходить access. Каталог должен работать без аккаунта GitHub.

**Файлы:** `src/lib/tg.ts`, `src/screens/academy/Catalog.tsx`, focused SDK mock/SSR tests (новые файлы при необходимости); существующие academy/navigation tests. Не менять библиотеку артефактов/FreeStart/S1/S2.

**Приёмка:** new/old/absent WebApp SDK не падает, `lockOrientation` не вызывается общей инициализацией; допустимый курс открывается по существующему guard, inaccessible не раскрывается; Back работает; landscape/portrait CSS без скрытых действий. Аппаратный Telegram тест остаётся честно отдельным, если устройство недоступно. Не утверждать, что это решает все accessibility-проблемы.
