# OG CRE8R: визуальные улучшения и инструменты

Исследование 6 ноября 2026. Основано на текущем коде, последней сборке, пяти скриншотах локального OG и актуальной официальной документации. Это предложения следующего этапа; установка библиотек и реализация нового оформления в исследование не входили.

## Рекомендуемое направление

**Мастерская результатов.** На входе — выразительные обложки и конкретный следующий шаг. Внутри урока — спокойное чтение, видимые действия и образец того, что нужно получить. Сохранить Onest, Unbounded, сиреневую основу и игровые акценты, но распределить их по роли экрана.

| Приоритет | Наблюдение | Конкретное улучшение |
| --- | --- | --- |
| 1 | В тёмной теме белый текст на сиреневой основной кнопке имеет расчётный контраст 2.71:1. В светлой теме эта пара даёт 5.34:1. | Ввести отдельный цвет текста основной кнопки для каждой темы. Тёмные чернила на текущем светлом сиреневом дают 6.70:1. Светлую декоративную мяту отделить от более тёмного текста успешного состояния. |
| 1 | На скриншоте 320 px до начала материала занято около 560 px, широкий заголовок переносится на четыре строки. | Компактная шапка «Урок 1 из 6», номер отдельно от названия, адаптивный заголовок, краткая цель урока. Весь крупный декоративный заголовок оставить на странице курса. |
| 1 | Вкладки самопроверки и ресурсов скрываются справа в полосе без видимого скролла; при чтении управление уезжает вверх. | Закрепить компактное управление «Читать / Делать / Проверить», все дополнительные разделы показывать в явном меню. При выборе раздела его начало должно попадать в видимую область. |
| 2 | OG-карточки используют одинаковую сиреневую подложку и emoji. Готовый CourseArtwork есть, но его общий мотив — один и тот же куб. | Сделать пять разных предметов результата в общей визуальной рамке: основы — бриф с проверкой; текст — документ с редактурой; медиа — кадры и таймлайн; код — мини-форма и тесты; автоматизация — узлы и готовый отчёт. На странице курса добавить реальный учебный образец итогового проекта. |

| 2 | Сохраняются урок и отметка прохождения; при переходе внутри курса скролл сбрасывается. | Сохранять раздел или устойчивый якорь, показывать «Продолжить с шага 3». В программе выделить следующий урок и показать сегменты завершённых занятий. |

Ориентир для обычного текста — 4.5:1, для крупного — 3:1: [официальное пояснение W3C](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). Числа выше рассчитаны по цветовым токенам; состояния на градиентах и полупрозрачных поверхностях дополнительно нужно измерять после реализации.

## Что переиспользовать

- `src/screens/courses/CourseArtwork.tsx`: локальные SVG/CSS, остановка вне экрана, при скрытой вкладке и reduced motion. Сохранить эту механику для новых обложек.
- Motion, Lucide, Tailwind, Markdown-копирование, увеличение картинок, адаптивные таблицы и учебные анимации уже подключены. Они покрывают большую часть предложенного оформления.
- `public/learning/ai-practice/paths/*.svg` — схемы последовательности, а не образцы результата. Текст 27 px в SVG шириной 800 px при показе на 280 px уменьшается примерно до 9.45 px. Для самого маршрута лучше адаптивные HTML-блоки.

## Проверенная подборка инструментов

| Инструмент | Применение здесь | Решение и ограничения |
| --- | --- | --- |
| [Motion](https://motion.dev/docs/react-accessibility), уже установлен | Переходы шагов, состояния прогресса, раскрытие самопроверки, небольшие SVG-иллюстрации. | Использовать текущую библиотеку. Уважать reduced motion. [LazyMotion](https://motion.dev/docs/react-reduce-bundle-size) можно оценить отдельно: сохранённые импорты обычного motion отменяют ожидаемую экономию. Конкретное уменьшение бандла требует замера. |
| [axe-core](https://github.com/dequelabs/axe-core) и [Lighthouse](https://developer.chrome.com/docs/lighthouse/overview) | Проверять контраст и доступность ключевых состояний, сравнивать загрузку до и после визуальных изменений. | Первый инструментальный шаг. axe — для тестов, Lighthouse доступен в Chrome; не требуется добавлять их в пользовательский бандл. Автоматический аудит дополнять ручной проверкой фокуса, чтения и Telegram WebView. |
| [Shiki](https://shiki.style/guide/) | Подсветка JS/TS, JSON, HTML и команд, подписи языков и акцент важных строк в уроках по коду и автоматизации. | Сейчас копирование кода уже есть, подсветки нет. Предпочтительно генерировать токены при сборке; для динамического контента выбирать ограниченные языки и темы. [Официальные рекомендации производительности](https://shiki.style/guide/best-performance). Полный клиентский импорт может добавить лишний вес. |
| [Base UI Drawer](https://base-ui.com/react/components/drawer) | Одно мобильное оглавление/панель инструментов с управлением фокусом, жестом закрытия и высотами раскрытия. | Подключать при конкретном сценарии панели. Компоненты без готового оформления сохраняют бренд OG. [Peer dependencies](https://github.com/mui/base-ui/blob/master/packages/react/package.json) включают React 19. Проверить экранную клавиатуру и скролл в Telegram на iOS/Android. |
| [Fuse.js](https://www.fusejs.io/) | Поиск конкретных уроков с опечатками и ранжированием названия выше описания. | Позже, после прямых результатов по урокам. На пяти курсах текущего поиска может хватать. Русскую морфологию, синонимы и транслитерацию не добавляет автоматически. |

Совместимость React у Base UI подтверждена декларацией пакета. Остальные предложения проверены по документации, но не устанавливались и не компилировались с текущими TypeScript 7/Vite 8 в рамках исследования.

**Отсев:** [Vaul](https://github.com/emilkowalski/vaul) в официальном README помечен как неподдерживаемый. [Rive](https://rive.app/docs/runtimes/web/web-js) имеет отдельный JavaScript/WASM runtime и Canvas/WebGL варианты; оправдан, когда появится подготовленная интерактивная учебная сцена. Для предлагаемых сейчас обложек и переходов достаточно существующего стека.

## Загрузка курса

В текущей сборке `Courses` занимает 776.71 kB / 147.23 kB gzip, статически связанный `Learning` — 224.43 kB / 52.61 kB gzip. `OGPractice.tsx` импортирует около 630 kB исходного JSON с телами всех 33 уроков. При этом лёгкий каталог уже существует отдельно.

Практическое изменение: каталог читает только метаданные, текст курса загружается при открытии, старые Academy-экраны подключаются отдельными ленивыми маршрутами. Это размеры файлов сборки, а не измеренное время загрузки; точный выигрыш покажет новая сборка и холодный браузерный замер.

Ещё два небольших улучшения: расширить область нажатия кнопки копирования Markdown с 36 до 44 CSS px и добавить общий focus-within для поиска. Сейчас пользовательский focus-стиль привязан к контейнеру `.academy`, которого нет у основного каталога.

## Порядок следующего этапа

1. Исправить контраст и фокус, сократить шапку урока, сделать разделы видимыми; снять исходные показатели доступности и загрузки.
2. Сделать пять обложек с реальными образцами результата, облегчить главную и оформить следующий урок; отделить загрузку каталога от текстов.
3. Добавить раскрываемую самопроверку и Shiki. Подключать Drawer и Fuse по конкретной потребности.

Проверка результата: светлая/тёмная тема, 320/390 px и крупный текст, reduced motion, клавиатура и экранный диктор, реальный Telegram iOS/Android, холодное открытие каталога и урока. Существующие девять браузерных сценариев сохранить как регрессионную основу.
