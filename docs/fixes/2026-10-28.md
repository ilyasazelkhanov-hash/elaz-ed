## Обновление учебных пакетов

Публикация сохраняет снимки управляемых узлов в `aa_content_node_receipts`. Следующий выпуск обновляет только изменившиеся узлы и проверяет, что сохранённый снимок совпадает с БД. Ручная редактура останавливает транзакцию. Неизменённые проверки сохраняют версии и лимиты попыток.

Для пакета, выпущенного старым CLI, можно передать `--baseline=/path/to/previous-catalog.learning.json`: это каталог **фактически предыдущего выпуска**, который нужно извлечь из его коммита/артефакта. Текущее состояние БД обязано совпасть с его опубликованными полями. Несовпадения не перезаписываются. Тест проверяет обновление, сохранность версий, переход со старой публикации и отказ при ручном изменении.

Экспорт без записи в БД:

```sh
npm run academy:release -- --actor=TELEGRAM_ID --course=CORE-000
```

## Порядок применения

1. Сверить историю рабочей базы. Применить **две новые миграции** `20261028090000_core_atomic_operations.sql` и `20261028091000_academy_version_policy.sql`. Ранее применённые миграции не переписывались. Не запускать вслепую полный `db push` и не исправлять историю автоматически.
2. Развернуть обновлённую `supabase/functions/api`. Новая функция требует новые RPC из миграций, поэтому SQL применяется первым.
3. Развернуть frontend из `main`. При необходимости опубликовать обновлённые учебные пакеты проверенным SQL-экспортом.
4. В рабочем Telegram проверить вход, отзыв административного доступа, чтение, восстановление квиза и сохранение работы. Реальные сообщения и платежи при локальных проверках не выполнялись.

Для выполнения из облачной среды токен Supabase добавляется через защищённые настройки среды, а не в чат или Git. Также нужен сетевой доступ к Supabase Management API и рабочим адресам.
