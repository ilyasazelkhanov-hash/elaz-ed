# Бесконечная лента блога и продвижение

В главной ленте и отдельном блоге публикации автоматически подгружаются при прокрутке до самого старого поста. Ограничение загрузки блога первыми 300 записями устранено: отдельный защищённый маршрут `blog_feed` выдаёт страницы по 30 записей. В конце архива появляется сообщение, что пользователь дошёл до первой публикации. Кнопка «Ещё публикации» доступна для ручной подгрузки; после ошибки есть повтор без потери уже загруженных записей.

Путь администратора: **Профиль → Админка → Публикация → «Продвигать» → Сохранить / Опубликовать**. Отметка доступна и для редактирования существующих публикаций. Продвигаемые посты идут первыми (сначала новые), затем весь остальной архив от новых к старым. Отметку можно снять. В списке админки виден статус «Продвигается».

Используется существующее поле `pinned` и защищённое сохранение `admin_save`; миграция схемы не требуется. У сторис и курсов прежние настройки сохранены. Статьи не превращаются в уроки; лента исключает сторис, материалы курсов и черновики. Доступ требует действующей подписи Telegram и подписки. Поиск, категории и непрочитанные применяются к загруженным записям; если совпадений мало, автоматическая подгрузка продолжает проходить архив.

Курсор содержит группу продвижения, дату и ID, а не смещение: равные даты не нарушают порядок. Переход к непродвигаемой группе явный; учтены записи без даты. Клиент исключает дубликаты и параллельные запросы, игнорирует устаревшие ответы после смены пользователя или выхода со страницы. Редактор обновляет ленту после изменения статуса продвижения.

## Проверки

- TypeScript/Vite production build.
- API: 86 тестов, включая полный проход 367 записей, больше страницы продвигаемых записей, равные и пустые даты, исключение черновиков/сторис/курсов, авторизацию, ошибку БД, продвижение и снятие отметки только администратором.
- Модели интерфейса и навигация: 7 тестов, включая единый порядок публикаций.
- `node scripts/blog-feed-browser.cjs`: локальная production-сборка с синтетическим API; автоматическая прокрутка архива из 367 постов без повторов, повтор после 500, полная лента на главной с сохранением геймификации, сохранение и снятие продвижения в админке. Ширины 320/390/1024, ошибок JavaScript нет. Рабочий Telegram этим сценарием не проверяется. [Машинный результат](blog-feed/checks.json).

## Выкладка

Frontend и Edge Function должны быть выпущены вместе. Новый маршрут находится в `supabase/functions/api/index.ts`. Пример из настроенной среды с безопасно сохранённым токеном Supabase:

```sh
supabase functions deploy api --project-ref dcdepwdxvadhludnubis --no-verify-jwt
```

JWT-шлюз отключён по существующей конфигурации проекта; сама функция проверяет подпись Telegram. Новый SQL не нужен. В текущей среде нет `SUPABASE_ACCESS_TOKEN`, поэтому рабочая серверная выкладка не выполнена. Коммит в GitHub не является подтверждением её выполнения. Пока функция не обновлена, клиент сохраняет начальные публикации и показывает ошибку подгрузки; сообщение о завершённом архиве при ошибке не выводится.
