# Уроки, квизы и модальные окна · 9 ноября 2026

Изменения внесены в самостоятельный мастер и независимую копию OG. Конфигурация клиентов, каталог, миграции и облачная БД не меняются.

## Поведение

- Запросы изменения состояния выполняются по очереди. Нажатие начала квиза при другом запросе не теряется; одинаковые ожидающие вызовы объединяются. Ошибка одного запроса не блокирует следующие. Новая сессия приложения получает отдельную очередь, старые ответы не заменяют её состояние.
- Текст домашней работы и ссылка на уже загруженный файл сохраняются синхронно в sessionStorage с ключом приложения, пользователя, demo/live и урока. При недоступном хранилище остаётся память текущей страницы с честной подписью. Закрытие вкладки завершает сеанс. Успешная отправка очищает только отправленную версию, не более поздний текст. Незавершённый upload не прикрепляется к другому экрану.
- Экран квиза хранит активную попытку и подтверждённые сервером ответы в памяти сессии API. Уход и возврат внутри приложения сохраняют вопрос, ответ и объяснение, в том числе при незавершённом запросе и тренировке. После перезагрузки обычная наградная попытка восстанавливается сервером; тренировка может начаться заново. При истечении серверного срока есть явное повторное открытие. Новая тренировка запускается кнопкой, а не при каждом возврате на экран.
- После завершения показаны только реальные ошибки: выбранный и правильный ответы, авторское объяснение, тема и переход к материалу урока, когда связь с уроком известна. Ключи будущих вопросов не запрашиваются. При восстановлении разбор читается идемпотентным повтором уже зафиксированных ответов.
- Диалоги удерживают Tab/Shift+Tab, не фокусируют скрытые/недоступные элементы, возвращают случайно ушедший фокус и восстанавливают opener при закрытии. Изменение callback при вводе не сбрасывает фокус. Вложенный диалог владеет клавиатурой, пока открыт.

В основном OG также добавлены итоговый разбор из зафиксированного feedback, возврат к уроку и сохранение места чтения. Academy сохраняет ввод в рамках сеанса и сверяет серверную попытку и состав вопросов при восстановлении. Её текущий API отдаёт только балл/статус: интерфейс честно сообщает, что подробного разбора нет. Связей «вопрос → точный подраздел» в текущих данных нет, поэтому используются ссылки на известный урок, а не выдуманные фрагменты.

## Проверки

- `npm test`, `npm run test:server-types`, `npm run build` из папки мастера.
- `npm run test:learning-resilience`, `npm run test:roadmap`, `npm run test:all` из корня OG.
- Новые регрессии проверяют очередь и ошибки, смену аккаунта/API, сохранение текста, позднюю отправку, состояние квиза при навигации, корректность черновика и focus trap. Focus-тесты используют управляемую модель DOM, не полноценный браузер.

Локальный Chromium не запустился: создание socket для профиля запрещено средой. Браузерная и мобильная приёмка не засчитаны. Production Telegram, платежи, загрузка в облачный Storage и серверная БД не менялись и этим выпуском заново не проверялись. Production build сохраняет предупреждение о размере отдельного чанка Three.js.
