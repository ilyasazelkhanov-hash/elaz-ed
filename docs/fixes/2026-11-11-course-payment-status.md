# Состояние оплаты OG CRE8R

## Изменение

Каталог, программа, закрытый урок и бесплатный пробный урок используют один компонент состояния оплаты. После результата Telegram `pending` покупка заменяется на «Проверить доступ». После `paid` показывается «Оплата прошла, ожидаем доступ», пока сервер не вернул `course.access=true`. После отмены и ошибки остаётся понятное сообщение и возможность проверить доступ до новой попытки.

Проверка доступа выполняет только существующий авторизованный `boot`: не создаёт счёт, не запрашивает бесплатный доступ, не открывает Telegram invoice. Повторные нажатия блокируются. Сбой сети не превращает подтверждённую Telegram оплату в ошибку оплаты. Нет обещания конкретного срока выдачи доступа или утверждения, что звёзды не списаны.

При открытии каталога после перезагрузки, возвращении фокуса, `pageshow`, `visibilitychange` и Telegram `activated` приложение проверяет незавершённую покупку. Повторные события ограничены одним запуском в пять секунд. Если callback Telegram потерялся, через 60 секунд отображается неизвестный результат вместо вечной блокировки или предложения платить снова. Позднее открытие доступа определяется сервером.

Если callback приходит позже 60 секунд, его результат сохраняется в исходном аккаунте и курсе. Поздняя отмена или ошибка возвращает возможность новой попытки; `paid` и `pending` запускают только проверку серверного доступа. Уже подтверждённый сервером доступ не заменяется устаревшим локальным статусом.

## Границы и безопасность

- Хранятся только статус интерфейса и время, отдельно для пользователя, курса и demo/Telegram. Ссылки на invoice, данные карты, Telegram auth и charge ID не сохраняются.
- Локальное состояние никогда не выдаёт доступ. Подделка localStorage может изменить сообщение, но не открывает платный материал. Доступ по-прежнему определяют `course.access` и авторизованный API уроков.
- Закрытие приложения во время открытого счёта сохраняется как неизвестный результат. Незавершённый статус не истекает автоматически и не разрешает новую покупку по таймеру. При долгом ожидании показана существующая команда бота `/paysupport`.
- Смена пользователя не переносит состояние оплаты или результаты проверки в другой аккаунт.
- Это восстановление на том же браузере/устройстве. Очистка localStorage или новое устройство не восстанавливают историю Telegram callback. Серверная история статусов и синхронизация между устройствами требуют отдельного read API.
- Миграций нет. Не менялись создание purchase intent, выдача доступа, pre-checkout и refund. Production БД и реальные платежи не использовались.

## Проверки

`npm run test:course-payment` покрывает состояния оплаты, отказ/ошибку/отмену, неизвестный результат, потерю callback, повторные нажатия, read-only recovery, сбой сети после `paid`, перезагрузку, смену пользователя, повреждённое/недоступное хранилище и отключение обработчиков возврата. UI-тест выполняет настоящий компонент с поддельными Telegram/API и синхронными тестовыми React hooks, не обращаясь к production.

Дополнительно: `npm run test:og-practice`, `npm run test:discovery`, `npm run test:review-resilience`, `npm run test:audit-remediation`, `npm run test:api`, `npm run build`.

Настоящий Telegram invoice и задержку webhook следует проверить отдельно в тестовом окружении перед выпуском; офлайн-тест не заменяет проверку провайдера.

Локальный результат: payment 22/22, og-practice 27/27, discovery 31/31, review-resilience 46/46, audit-remediation 15/15, API 109/109; TypeScript и production build прошли. Build сообщает о крупных чанках, как и до этого изменения. Полный `test:all` не запускался. Браузерная визуальная проверка не состоялась: cloud browser не смог подключиться к локальному Vite (`ERR_CONNECTION_REFUSED`), включая разрешённый запуск сервера вне сетевой изоляции.

При интеграции двух правок дополнительно проверены поздние `paid`, `pending`, `cancelled`, `failed`, смена аккаунта и уже открытый доступ: payment 28/28. Тестовый стенд аналитики обновлён для исполнения нового компонента и настоящих модулей состояния/checkout: roadmap 42/42. Независимое ревью подтвердило, что локальное состояние не выдаёт доступ и результаты не переносятся в другой аккаунт. Итоговые результаты общего прогона приведены в отчёте интеграции.
