# Dots Studio: выразительный персонаж и полные реплики

## Основание

После live 750a081 пользователь отметил, что маленькая CSS-капля не выглядит достаточно выразительно. Отдельная корректировка: реплики должны быть облачками, заголовки не должны обрезаться. Этот пакет относится к новому прямому запросу пользователя, а не к read-only автоматизации.

## Дизайн

- Компактная авторская сцена: тело с собственным силуэтом, лапки, крупные глянцевые глаза, брови, щёки, отдельный рот, аксессуары.
- Сатиновый материал и студийный свет вместо хаотичных частиц. Взгляд следует раньше корпуса; касание вызывает короткий пружинный отклик. Жест радости завершается, не превращается в вечное махание рукой.
- Справа настоящее speech bubble. Имя и настройка находятся в отдельной строке, поэтому кнопка меню больше не отнимает колонку у всего текста. Полные названия статей переносятся без ellipsis/nowrap/clamp. Высота зависит от текста, сцена не превращается в большой hero.
- Отметка и адвент остаются сразу под персонажем. Все существующие CTA, приватность настроек и доступная навигация сохранены.

## Архитектура

- `dots/rig.ts`: чистая детерминированная математика поз, пределы, выражения и затухание реакции.
- `dots/renderer.ts`: процедурная Three.js-сцена. Внешних моделей, текстур, запросов и новых зависимостей нет. Библиотека уже была в проекте.
- `dots/DotsCharacter.tsx`: ленивый запуск только после видимости; честный SVG до загрузки и при любой недоступности. Автоматический cleanup при unmount, изменении motion и ошибке контекста.
- `dots/DotsPoster.tsx`: полноценный оригинальный SVG для отсутствия WebGL, паузы или reduced-motion, со всеми формами/цветами/аксессуарами и эмоциями. При недоступности GPU остаётся лёгкая CSS-пластика без JS frame loop; пауза/reduced-motion дают статичный образ. Это не пустое место и не требование включить GPU.
- Максимум 30 отрисовок/сек, DPR до 1.5. Нет realtime shadows, transmission, postprocessing, загрузок моделей. Renderer/chunk не входит в статический entry; Three загружается только для видимого анимированного персонажа.
- RAF не планируется для невидимой/закрытой сцены, включая прокрученное за экран превью настройки. Delta ограничен после возврата из скрытой вкладки. Ошибки resize/render/context идут в один fail/dispose-path.

## Проверки

- `npm run test:companion` включает `dots-scene.test.mjs`: границы поз, reduced-motion, завершение реакции, lifecycle-контракты, все комбинации SVG, отсутствие обрезки.
- `scripts/home-companion-browser.cjs`: локальный demo, в том числе длинный заголовок на 320/390px; внешние запросы запрещены.
- SVG contact sheet реально просмотрен. Это проверка художественного fallback, не доказательство WebGL-рендера. Действительный WebGL и layout необходимо посмотреть в браузере после доступного развёртывания и отдельно зафиксировать результат.

## Реакции на устройство, без выдуманных возможностей

- Наклон и встряска включаются только кнопкой в «Движение, свет и голос». Никакого запроса разрешения при загрузке. На поддерживаемых Telegram 8.0+ используются `DeviceOrientation` и `Accelerometer`, в HTTPS-браузере предусмотрен Web fallback. iOS permission calls начинаются прямо внутри исходного click, до первого await.
- Статус `active` появляется только при реальных конечных показаниях, не по успешному вызову start. Нет показаний, запрет и частичная поддержка обрабатываются отдельно. Показания не сохраняются и не отправляются, настройки не имитируют постоянное разрешение ОС.
- Наклон относительно исходной позиции, с ограничением и сглаживанием, поворачивает только персонажа. Telegram передаёт радианы, Web API градусы. События изменённого Telegram-сенсора читают объект SDK, а не несуществующий payload.
- Встряска требует двух пиков после прогрева и имеет cooldown 3 секунды. Она меняет мимику и краткую реплику, но не вызывает навигацию, оплату, выдачу награды или иные действия. Порог является проектной настройкой, не проверенной на реальном телефоне калибровкой.
- При уходе, скрытии или перекрытии персонажа адаптер останавливается. Пауза/reduced-motion запрещают реакции сразу. Для нового просмотра нужно явное включение заново. Abort защищает от позднего permission grant. У SVG fallback также есть ограниченный наклон без дополнительного JS frame loop.
- «Светлячок в сцене» включает только нарисованный тёплый фонарик персонажа. Яркость экрана, камера и физический фонарь телефона не используются.
- Голос выключен по умолчанию. После opt-in появляется отдельная кнопка чтения текущей реплики и остановки. Автоозвучки нет, аппаратный mute/громкость не определяются, текст остаётся всегда. Предпочитается системный локальный русский голос; браузер может использовать сетевой голос, что явно объяснено в настройках. Микрофон не нужен.
- Свет/голос сохраняются отдельно по аккаунту только в этом браузере. Если сохранение заблокировано, честно сообщается о временном выборе.

Официальные основания, проверены 12.11.2026:

- [Telegram DeviceOrientation](https://core.telegram.org/bots/webapps#deviceorientation), [Accelerometer](https://core.telegram.org/bots/webapps#accelerometer).
- [Web orientation permission](https://developer.mozilla.org/en-US/docs/Web/API/DeviceOrientationEvent/requestPermission_static), [motion permission](https://developer.mozilla.org/en-US/docs/Web/API/DeviceMotionEvent/requestPermission_static).
- [Screen.mozBrightness](https://developer.mozilla.org/en-US/docs/Web/API/Screen/mozBrightness) нестандартен и устарел. [AmbientLightSensor](https://developer.mozilla.org/en-US/docs/Web/API/AmbientLightSensor) измеряет окружающий свет, не яркость экрана. [HTMLMediaElement.muted](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/muted) относится к отдельному плееру, не к аппаратному беззвучному режиму.

Дополнительные проверки: `companion-motion.test.mjs` проверяет синхронный opt-in, отказ, отсутствие показаний, разные единицы, abort/late callbacks, две волны встряски и cooldown. `companion-device.test.mjs` проверяет изоляцию предпочтений, отсутствие auto-play, отмену устаревших событий речи и недоступность голоса. Проверка реального телефона/сенсоров/аудио остаётся отдельным hardware QA, автоматические тесты её не заменяют.
