# 15 ноября 2026: серверные сезоны адвента, новость только для Mini App, честные ошибки базы

Статус: **код и тесты готовы в source, не опубликовано**. Миграции не применялись, Edge Function и frontend не разворачивались, production и реальные аккаунты не проверялись. Baseline: `2dead0f` (полный `npm run test:all` на нём: 50/50 этапов PASS в этой же среде).

## 1. Адвент: сезон на сервере вместо локального чек-листа (N12)

### Что было не так

Активный вход `5d1270` вёл в `Season.tsx`: 53 задания с отметками в localStorage, `xp: 0`, без `api.adventOpen`. Потеряны серверный XP и обновление профиля, `+XP`, звуки, `celebrate`, вибрация, квиз, скретч, аркада, серия, билеты, путь наград и коды. Простая перезапись дней 1-53 была невозможна: `advent_doors(day)` и `advent_opens(user_id, day)` не различали кампании.

### Что сделано

| Слой | Изменение |
| --- | --- |
| База | `supabase/migrations/20261115120000_advent_seasons.sql`: колонка `season` у дверей, открытий, призов и билетов (прежние строки получают `legacy`), ключи `(season, day)` и `(user_id, season, day)`, реестр `advent_seasons` со снимком настроек, `advent_active_season()`, сезонные `advent_open`, `advent_open_late`, `advent_summary`, розыгрыш в пределах сезона приза. Прежние сигнатуры функций сохранены и работают с активным сезоном |
| API | `supabase/functions/api/index.ts`: все чтения и записи адвента ограничены сезоном из `settings.advent.season`; `advent`, `advent_door`, `advent_open` принимают `season` для архива (только просмотр); ответ `advent` содержит `season`, `archived`, `archives`; `admin_advent_save` умеет сменить сезон, сохранив снимок прежних настроек |
| Контент | `content/advent/build-season.mjs` раскладывает 53 задания `ai-winter-2026.json` по дверям: 15 квизов (30 вопросов, план в `ai-winter-2026.doors.json`), 23 скретча (под слоем лежит промпт дня), 7 аркад, 8 историй. Тексты заданий не менялись. XP по видам повторяет прежний seed: 30 / 25 / 20 / 15, финальная дверь 50 |
| Frontend | Главная снова показывает серверный `AdventBanner` → `AdventScreen` → `DoorScreen` с `api.adventOpen`, `setMe`, `ResultCard`, звуками и `celebrate`. Архив прежнего сезона открывается кнопкой в календаре. В скретч-двери появилась кнопка «Скопировать текст» |
| Демо | `mockAdvent.ts` берёт двери нового сезона (`adventSeasonSeed.json`), ключ демо-прогресса `v2` |

### Что сохранено и чего сознательно нет

- Данные прежней кампании не удаляются и не пересчитываются: тест на PGlite сверяет строки открытий, XP и коды до и после миграции. Коды прежних призов по-прежнему гасятся на кассе.
- **Призы нового сезона не созданы.** Экономику задаёт владелец в Админка → Адвент → «Призы». Пока призов нет, блок наград в календаре не показывается, XP за двери начисляется.
- Билеты действуют в своём сезоне. Неиспользованные билеты закрытой кампании не переносятся: после её закрытия ими и раньше нельзя было воспользоваться. Способы получения и цена билета наследуются из прежних настроек.
- Локальный календарь практик (`Season.tsx`) оставлен только как запасной вход: он показывается, пока сервер не сообщает об идущем календаре. Иначе выпуск frontend раньше backend убрал бы вход с главной. После включения сезона на сервере локальные отметки больше не показываются; из localStorage они не удаляются. XP за них не начислялся и задним числом не начисляется.

### Порядок выпуска (каждый шаг требует отдельного разрешения и квитанции)

1. Резервная копия и инвентаризация: `settings.advent`, число строк `advent_doors`, `advent_opens`, `advent_rewards`, `advent_tickets`, `reward_codes`.
2. Применить `20261115120000_advent_seasons.sql`. Прежний API продолжает работать: активный сезон `legacy`.
3. Развернуть Edge Function `api`.
4. Выполнить `content/advent/ai-winter-2026.seed.sql` (53 двери, сезон не включается).
5. Задать призы в админке, если они нужны (после шага 6 новые призы создаются уже в новом сезоне; до него в прежнем).
6. Выполнить `content/advent/ai-winter-2026.activate.sql`: снимок прежних настроек, включение сезона, сброс курсора пушей.
7. Выпустить frontend. Проверить в реальном Telegram: баннер, открытие двери дня, `+XP` в профиле, повторное открытие без второго начисления, архив прежнего сезона.

Откат шага 6: `update settings set value = value || '{"season":"legacy"}' ...` либо `admin_advent_save` с `season: 'legacy'` (поднимает снимок). Открытия нового сезона при этом остаются в базе под своим id.

### Решение, которое остаётся за владельцем

Старт сезона по требованию 14 ноября. Если включение произойдёт позже, двери прошедших дней окажутся «пропущенными»: по прежним правилам их открывают за билет и за половину XP. Варианты: принять как есть; выдать участникам билеты; сдвинуть `start` на день запуска (тогда 53 дня закончатся позже 5 января). В код ни один вариант не зашит.

## 2. Новость только для Mini App (N07)

`supabase/migrations/20261115130000_news_telegram_optout.sql`: `lessons.telegram_publish boolean default true`; `claim_news_post` не берёт новости с `false` и блокирует выбранную строку до записи о начатой отправке. API принимает поле в `admin_save`, ручной анонс такой новости отклоняется (`miniapp_only`). В редакторе публикации переключатель «Публиковать в канале». `news_eligible` и общий cron не трогаются: новость остаётся в ленте и блоге, остальные выходят как раньше.

Новость Swarm этим изменением **не опубликована**. Порядок: применить миграцию → развернуть `api` → создать новость с выключенным переключателем → убедиться, что в `news_publications` для неё нет строки.

## 3. Сбой базы не выглядит как отказ (часть N09)

`member`, `hasAccess`, `canRead`, `lesson`, `quiz_start`, `quiz_answer`, `complete`, `buildCourses` теперь отвечают `500 db`, если чтение не удалось. Раньше сбой мог выглядеть как `401 no_user`, `403 course_locked`, `404 not_found`, «урок не пройден» или пустой каталог у человека с купленным курсом.

Не входит: различие смысла нулевой цены в OG и Academy (нужно продуктовое решение), дедлайн precheckout мастера, развёртывание защиты удаления курсов, backup/restore.
