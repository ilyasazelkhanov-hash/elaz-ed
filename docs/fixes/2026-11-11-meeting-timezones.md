# Часовые пояса встреч

## Поведение

- В карточках событий/слотов и в блоке ближайшей встречи указано UTC-смещение на дату встречи. Для текущей настройки OG это `UTC+05:00`.
- В деталях встречи показаны дата, время, имя настроенного часового пояса и его смещение, например `22 ноября 2026 г. в 18:30 · Asia/Qyzylorda (UTC+05:00)`.
- Редактор явно различает часовой пояс устройства и приложения. Рядом с `datetime-local` указан пояс устройства со смещением для выбранной встречи; под полем обновляется предварительный результат для участников.
- Ввод остаётся локальным для устройства, а сохранение — ISO UTC. Существующие значения, настройки приложения, API и БД не менялись. Пустая/неверная дата не порождает выдуманное время.
- Одинаковая реализация находится в самостоятельном `Azelkhanov-master` и встроенном `src/platform-kit`; каждая копия импортирует только собственные файлы.

## Ограничения

Живой мобильный интерфейс и сценарий редактирования/сохранения в браузере в этой среде не подтверждены: локальный Chromium не запускается из-за ограничения сокетов, отдельный браузер не видит локальный dev-сервер. До окончательной UI-приёмки проверить узкую ширину 320/390px, редактирование встречи из другой зоны, сохранение, повторное открытие и отмену изменений.

Переходы DST для `datetime-local` сохраняют прежнее поведение JavaScript: несуществующий час переносится вперёд, при повторяющемся часе новый ввод выбирает первое вхождение. Предварительный результат отражает фактически выбранный момент; существующий ISO-момент не переписывается без редактирования.

Публикация, production-БД, реальные оплаты и отправка сообщений не выполнялись.
