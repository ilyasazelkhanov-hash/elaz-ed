# UI/UX и доступность — локальная проверка

Дата: 28 октября 2026. Проверены исходная сборка cc14551 и повторная production-сборка текущих изменений админки и базы знаний после npm run build. Скриншоты 01–13 в ui/ — финальный повторный запуск. Доказательства свежего запуска находятся в `ui/`, данные и Telegram-контекст синтетические. Живой Telegram, устройство пользователя, screen reader и настоящая Supabase не проверялись. Это не заключение о соответствии WCAG всего продукта.

## Подтверждённые проблемы исходной версии

### UI-1 · P2 · Клавиатурный фокус остаётся под открытой публикацией

- Место: `src/screens/Post.tsx:23`, `src/App.tsx:140–156`.
- Шаг: Блог → нажать карточку публикации → нажимать Tab.
- Факт: после открытия `document.activeElement` остаётся на закрытой карточке блога. Следующие фокусы: Главная → Рейтинг → Профиль, все под экраном публикации; только затем кнопка «Назад» публикации. После последней кнопки публикации фокус снова уходит в фоновый документ.
- Риск: клавиатурный пользователь или пользователь ассистивной технологии меняет раздел приложения, не видя активную кнопку. У открывшегося экрана нет управляемого начала фокуса и изоляции фоновых элементов.
- Доказательство: `ui/checks.json`, поля `focusAfterOpen` и `tabSequence`; свежие экраны блога/публикации.
- Исправление: при открытии верхнего экранного overlay переводить фокус внутрь, исключать фон и нижние overlay из tab/assistive tree (`inert`), возвращать фокус в открывший элемент при закрытии. Проверять стек overlay, а не только одну публикацию.

### UI-2 · P2 · Белый текст основной градиентной кнопки имеет недостаточный контраст

- Место: `src/index.css:38`, `src/index.css:313`, `src/index.css:327`; стандартная кнопка `src/ui.tsx:314`.
- Шаг: Курсы → AI Foundations → «Открыть первый урок».
- Факт: `.cta` задаёт 14 px / weight600; `.cta-aurora` использует белый текст на `#7c6bff → #b26bff → #ff85c0`. Расчёт относительной яркости даёт соответственно 3.89:1, 3.26:1 и 2.24:1 — ниже 4.5:1 для этого размера текста.
- Доказательство: свежий `ui/05-program.png`; исходные переменные градиента и computed-style проверки.
- Риск: важная кнопка труднее читается при слабом зрении/ярком свете. Это касается всех кнопок стандартного aurora-tone, а не только курса.
- Исправление: сохранить яркий градиент, но выбрать проверенный тёмный цвет текста либо затемнить подложку.

### UI-3 · P2 · Бонус дня недоступен с клавиатуры

- Место: `src/screens/home/Daily.tsx:102–111`.
- Шаг: Главная → пройти Tab к кнопке ежедневного бонуса → активировать Enter/Space.
- Факт: управляющий элемент — `motion.div role="button"` без `tabIndex` и без keyboard-handlers. В нативном Tab-порядке он отсутствует; фокусировка `.focus()` не выбирает этот div. Начисление запускают только pointer-события.
- Риск: пользователь клавиатуры не может выполнить ежедневное действие, хотя оно представлено как кнопка. Увеличенные размеры подарка не решают доступность.
- Исправление: нативная `<button>` с поддержкой клавиатуры; для keyboard-activation предоставить нормальное нажатие либо доступное удержание клавиши, не повторяющее запрос при autorepeat. Учитывать busy/disabled.
- Доказательства: свежий экран `ui/01-home.png`, source и runtime `dailyKeyboard` в итоговом `checks.json`.

## Проверенные шаги

1. **Главная — основной путь исправен.** Уровень/XP/стрик/бонус видны в первом viewport390×844. Меню содержит Главная/Рейтинг/Профиль. Снимок `ui/01-home.png`.
2. **Блог — основной путь исправен.** Поиск, категории, отдельные публикации и завершение архива видны. Карточка не обещает квиз/зачёт/XP. Снимок `ui/02-blog.png`.
3. **Публикация — чтение работает, клавиатурный фокус требует исправления UI-1.** Отдельный reader, авторский текст и действия лайка/поделиться. Ранний снимок со скелетоном отклонён и сохранён в rejected/; принятый финальный `ui/03-post.png` переснят после появления заголовка Markdown. Внизу видны связи с двумя подходящими курсами.
4. **Каталог — основной путь исправен.** Карточки, поиск и темы доступны; предупреждение отдельно сообщает о границе чтения/серверной проверки. Снимок `ui/04-courses.png`.
5. **Программа — основной путь исправен, контраст UI-2.** Материал доступен, основной CTA ведёт в настоящий урок, зачёт отделён. Снимок `ui/05-program.png`.
6. **Урок — основной путь исправен.** Номер урока/модуля, объяснение, четыре этапа и переходы присутствуют. На узком экране первым виден понятный учебный абзац (снимок `ui/06-lesson.png`). На320/390/768/1024 горизонтального переполнения документа нет.
7. **Профиль → админка — вход исправен.** Финальный хаб содержит отдельные Блог/Сторис/Материалы курсов (`ui/07-admin.png`). Проверены отдельные списки и создание записей: блог содержит переключатель продвижения без квиза, сторис содержит слайды и XP за просмотр без продвижения (`ui/10-admin-blog.png`–`ui/13-story-settings.png`).

Клиентских JavaScript-ошибок в сценарии не было. Сеть учебного API в сценарии намеренно возвращает503, чтобы проверить честно доступное публичное чтение; эти результаты не подтверждают серверный LMS/платёж/настоящую подписку. При prefers-reduced-motion:reduce computed animation-name у куба обложки — none. Полную работу со screen reader, движением в остальных компонентах и цветовые темы целиком не проверяли.

8. **База знаний — основной путь исправен.** Есть выбор «Я начинаю»/«Уже практикую», темы, пояснение практической задачи и подходящий курс. Переключение практик → Автоматизация предлагает AU-201 и говорит о повторах/восстановлении (`ui/08-knowledge.png`, `ui/09-practitioner.png`). Это явные учебные подборки; живые трендовые новости синтетическими данными не проверялись.

Поле JSON `homeGameInViewportAfterHubScroll` помечено отдельно: это измерение после прокрутки к базе знаний, а не положение элементов при входе. Начальную видимость подтверждает принятый снимок01.
