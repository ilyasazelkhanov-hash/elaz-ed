# Аудит и разделение админки

Проверен исходный cc14551 и реализовано требование пользователя в текущем рабочем дереве. Рабочие Telegram и Supabase не изменялись.

## Подтверждённые проблемы исходной версии

1. **P1: старые публикации недоступны редактору после 500 смешанных записей.** `adminList` в `supabase/functions/api/index.ts` выбирал `.limit(500)` без разделения типов и пагинации. При 620 статьях и наличии сторис/уроков старую статью нельзя было ни найти, ни отредактировать. Публичная бесконечная лента это не исправляла.
2. **P2: общий список смешивал статьи, сторис и старые учебные уроки.** `src/screens/Admin.tsx` выводил весь `d.lessons` сразу. Два действия создания внизу не объясняли, какие настройки относятся к какому виду материалов. Актуальные курсы находились по отдельной ссылке, архивные уроки продолжали выглядеть как обычные записи.
3. **P2: ошибка списка не имела явного повторного действия.** Ошибка `adminList` показывала только toast, список мог оставаться в состоянии начальной загрузки.

## Реализация

- Хаб «Админка» содержит три раздела: **Блог / Сторис / Материалы курсов**. В хабе нет смешанного списка.
- Блог и сторис имеют свои overlay-экраны, отдельный список, создание и поиск по заголовку по всему разделу. Нативная Telegram BackButton возвращает из редактора в нужный список, из списка — в хаб.
- Новый `admin_list` принимает `scope: blog | stories | legacy | summary`. По умолчанию старый контракт сохранён. Для отдельных списков используется курсор ID и страницы по 30 записей, что устраняет общий лимит 500. Сервер фильтрует тип и связь с курсом **до** ограничения страницы. Заголовки ищутся на сервере; `%`, `_` и `\` трактуются буквально.
- В блоге настройки публикации и продвижения; нет управления XP, квизом или назначением в курс. В сторис — слайды, оформление и XP за просмотр, без настройки продвижения блога.
- Кнопка материалов курсов открывает актуальную LMS-админку `#/courses/admin`. Старые программы, платежи, выданные доступы и уроки размещены в явно названном архиве. В архивном редакторе убрана кнопка «Без курса», чтобы случайно не превратить учебный материал в статью блога.
- Аналитика и Адвент остаются отдельными инструментами. Записи и прогресс не переносятся и не удаляются.
- У списка есть отдельные загрузка, пустое состояние, ошибка и повтор. При старой серверной функции клиент дополнительно фильтрует виды материалов и сообщает, что для всего архива требуется обновление сервера, вместо смешивания типов.

## Проверки

- `npx tsc --noEmit` — успешно.
- `npm run test:api` — **89/89**, включая три новых теста: архив 620 статей + 400 сторис + 10 старых уроков без смешивания/потерь, поиск старого заголовка и буквальных `%_`, сохранённая авторизация администратора и ошибки базы.
- Новый `scripts/admin-sections-browser.cjs` проверяет реальные UI-действия в production-сборке с синтетическим API; результат и экраны сохраняются в `test-results/full-audit/admin/`.
- Существующие `scripts/blog-feed-browser.cjs` и `scripts/og-clarity-browser.cjs` обновлены на новый путь «Админка → Блог → Новая публикация», без ослабления сценариев ленты/курсов.

## Ограничения выпуска

Потребуется совместный выпуск frontend и обновлённой Supabase Edge Function `api`. Секрет для развёртывания в текущей среде отсутствует; рабочая серверная функция не обновлялась. Новая SQL-миграция не нужна. Браузерные проверки используют синтетические данные и не подтверждают рабочую публикацию.
