## Подтверждённые проблемы

### G1 · P1 · Блог снова представлен как учебный маршрут с XP

- Код: `src/screens/Experience.tsx:39`, `src/screens/Experience.tsx:50`, `src/lib/journey.ts:12`.
- Путь: главная → «Мой следующий шаг» → выбрать цель. JourneyScreen сначала оставляет только записи без course_id; это именно публикации блога по `isBlogPost`. Затем выводит счёт «0/N», полосу прохождения и `+N XP`, а нажатие открывает PostScreen.
- Следствие: пользователь видит новости как уроки с обещанными XP. PostScreen намеренно не вызывает завершение, поэтому новый пост в таком маршруте нельзя пройти. Даже новые публикации с XP=0 остаются «непройденными шагами». Реальные 28 курсов в этот маршрут не попадают.
- Доказательство: изолированная проверка вызывает настоящий routeLessons с постом; маршрут возвращает этот пост как шаг с XP, `isBlogPost` возвращает true. UI-формулировки подтверждены исходником; живой Telegram не проверялся.
- Исправление: строить маршрут по основному каталогу/урокам LMS и его серверному прогрессу. Рекомендации чтения блога показывать отдельно с «прочитано», без учебных XP/зачёта.

### G2 · P2 · Личное место не совпадает с местом на пьедестале при равных XP

- Код: `supabase/functions/api/index.ts:282`, `supabase/functions/api/index.ts:819`, `src/screens/Top.tsx:86`, `src/screens/Top.tsx:115`.
- Сценарий: два подписчика имеют 100 XP. buildMe считает `count(xp > myXp)+1`, то есть обоим выдаёт место 1. Список top сортирует XP, затем ID, а Top.tsx подписывает их как 1 и 2.
- Воспроизведено настоящим HTTP-handler + синтетическая БД: у пользователя id=2 ответ rank=1, но индекс в top равен 2. Получаются два разных личных места на одном экране.
- Ограничение: подтверждено для обычного рейтинга, когда `OG_PLATFORM_ENABLED` выключен. Платформенная SQL-функция использует row_number с тайбрейком и такого расхождения не имеет.
- Исправление: выбрать одинаковую политику ничьих на сервере и в UI. Для последовательных мест считать предыдущих с большим XP либо с тем же XP и меньшим ID.

### G3 · P2 · Ошибка выдачи достижения теряется после успешного начисления XP

- Код: `supabase/functions/api/index.ts:585`, `supabase/functions/api/index.ts:606`, `supabase/functions/api/index.ts:621`, `supabase/functions/api/index.ts:623`; аналогичный непроверяемый вызов в daily — `:638`.
- Сценарий: complete_lesson успешно фиксирует прогресс и XP, затем grant_achievements возвращает error. Код не проверяет error и возвращает HTTP 200 + `new_achievements:['first']`, хотя `me.achievements` остаётся пустым.
- Воспроизведено внедрением однократной ошибки только в grant_achievements при вызове настоящего API-handler. Повтор complete возвращает already=true и не пытается восстановить достижение. Оно может появиться при будущем подходящем завершении, но повтор исходного действия не исправляет состояние.
- Исправление: выдавать достижения атомарно с основным начислением либо иметь идемпотентную сверку на повторе/boot; не объявлять неподтверждённую выдачу успешной. Простого throw после начисления недостаточно без пути восстановления.
