# Аудит блога, ленты, продвижения и сторис

База: cc14551, 28 октября 2026. Аудит исходного кода и локальной production-сборки с синтетическим API. Рабочий Telegram/Supabase не проверен; внешние сообщения не отправлялись. Во время аудита другой агент дорабатывает разделение админки; выводы ниже относятся к указанному HEAD.

## Подтверждённые проблемы

### B1 · P1 · Старые публикации нельзя найти для продвижения/правки после 500 записей

`supabase/functions/api/index.ts:1000` — `adminList` выдаёт общий список всех видов материалов с `.limit(500)` без продолжения. В пользовательском блоге уже реализован полный архив, но администратор не может отметить самый старый пост для продвижения, если он вышел из этого окна. Смешанные сторис и уроки дополнительно вытесняют статьи.

Воспроизведение: 501 опубликованная статья; `admin_list` возвращает 500, ID1 отсутствует. Доказательство: `blog/audit-blog-repro.log`, строка `EVIDENCE admin_list`. Рекомендация: серверная пагинация отдельно по виду, фильтры и поиск по полному архиву, отдельный список учебных материалов. Root уже поручил исправление агенту админки.

### B2 · P2 · Блог вытесняет опубликованные сторис из главной

`supabase/functions/api/index.ts:428` — общий `buildFeed` сортирует все виды по pinned/дате и обрезает до 300. `src/screens/Home.tsx:20` и `src/screens/Stories.tsx:18` берут сторис только из этого массива; отдельной загрузки сторис нет.

Воспроизведение: 300 старых продвигаемых блогов + одна новая опубликованная непродвигаемая сторис. `boot.feed` содержит 300 статей и 0 сторис. Аналогично 300 более новых обычных статей скрывают старые сторис. Доказательство: `EVIDENCE boot` в логе. Рекомендация: загружать опубликованные сторис отдельным запросом/страницами, не делить с блогом одно окно; у курсов также собственный источник.

### B3 · P2 · Удаление сообщает об успехе при ошибке БД

`supabase/functions/api/index.ts:1045` — результат удаления не проверяется; маршрут всегда возвращает `{ok:true}`. Редактор после этого показывает «Удалено» и закрывается, хотя запись сохраняется и может продолжать публиковаться.

Воспроизведение: внедрённая ошибка Supabase delete. Ответ HTTP200 `{ok:true}`, запись остаётся в таблице. Доказательство: `EVIDENCE admin_delete` в логе. Рекомендация: проверять error, возвращать 500 при неудаче; не закрывать редактор и разрешить повтор. Удаление отсутствующей записи можно считать идемпотентным успехом.

## Дополнительный риск кода

`src/screens/Stories.tsx:34–45`: ID добавляется в локальный `rewarded` до завершения `api.complete`; при сетевой ошибке catch только вызывает guard и не удаляет ID. Повторный просмотр той же сторис в ещё открытом просмотрщике не повторит зачёт. После закрытия и нового открытия память сбрасывается. Это подтверждено чтением кода; отдельная браузерная попытка не достигла контрола открытия сторис, поэтому сценарий не отмечен как пройденный и не включён в три подтверждённых дефекта выше.

Права администратора на продвижение проверяются сервером. Очередь публикаций при неопределённой доставке останавливается преднамеренно; ручная сверка документирована в `docs/NEWS-PUBLISHING.md:21`, поэтому это не выдано за дефект дублей.

## Материал и ежедневная польза: рекомендации по реальным локальным данным

В `content/ai-practice-2026-10-25/reference-posts.json` есть практические публикации «Как выбрать ИИ-инструмент и не утонуть в каталогах», «ИИ-отчёт по таблице: сначала контрольные числа», «Автоматизация для бизнеса: карта процесса до запуска». Это подходящая база для маршрутов «выбрать инструмент → выполнить маленькую задачу → перейти к уроку». Например: таблицы → DT-101; карта автоматизации → AU-101; выбор инструмента и проверка результата → CORE-000. Связь лучше хранить явным кодом курса, а не выводить из совпадения названий.

В `content/elaz-ed-2026-10/payload.json` есть отдельные инструменты и визуальные приёмы: blocks.so, Sileo, GSAP Skills, Agentation. Их следует показывать в рубрике инструментов/приёмов, с конкретной задачей, ограничениями, датой проверки и ссылкой на первоисточник. Эти локальные записи не доказывают текущую свежесть продукта/функции; не маркировать их как «сегодня вышло» без повторной проверки источника.

Для новичков у материала нужен короткий ответ «что получится за 10 минут» и одно действие; для опытных — пример входных данных, критерий результата, ошибки и более глубокая ссылка. Существующие рубрики «Дизайн», «Промпты», «Автоматизация», «Текст и данные» подходят лучше общего «Прочее». Для ежедневного возвращения полезнее самостоятельная небольшая задача с результатом, чем просто новая карточка инструмента. Сторис могут вести к полной статье; статья — к конкретному уроку; навигация не должна превращать чтение блога в обязательный зачёт.
