# Публикации OG CRE8R²

Бот `@elazart_bot` публикует материалы ленты в `@OGCRE8R` (Telegram определяет его как канал). Настройка назначения хранится отдельно от канала проверки подписки: `settings.news_publishing`. Секрет `BOT_TOKEN` остаётся только в окружении Edge Functions.

## Поведение

- Выбираются опубликованные `lessons` с `kind=lesson` и `course_id is null`. Уроки внутри курса и черновики не рассылаются. Начальная выгрузка: 120 материалов.
- Порядок: `coalesce(published_at, created_at), id`, от старых к новым.
- Сообщение: обложка при доступности, заголовок, фрагмент содержания до 480 символов, видимая ссылка на конкретную статью и кнопка «Читать полностью». Telegram-caption укладывается в 1024 символа. Фрагмент берётся из текста статьи с удалением Markdown, служебных заголовков и изображений; это сокращённая выдержка, не отдельный ИИ-пересказ.
- Новые материалы попадают в ту же очередь автоматически после публикации. Планировщик проверяет её каждую минуту; до десяти сообщений за запуск, пауза минимум 5 секунд между попытками в одном чате. Во время выгрузки архива новые материалы ждут своей очереди.
- Изменение уже отправленной статьи не создаёт повторного поста.
- Кнопка анонса у новости не дублирует автопост: сообщает, что материал обрабатывает очередь. Анонсы курсов и историй по-прежнему отдельные ручные действия.
- Пользовательское «Поделиться» передаёт краткую выдержку и ссылку на статью, сохраняя выбор получателя и реферальный параметр. Для prepared inline message сервер проверяет доступ к статье; закрытые уроки не раскрываются.

## Доставка и восстановление

`public.news_publications` хранит назначение, материал, попытку, статус и Telegram message_id. Атомарный `claim_news_post` сериализует отправки; `finish_news_post` завершает только собственную попытку. У таблицы включён RLS, таблица и функции доступны только `service_role`.

При явном отказе Telegram сообщение не считается доставленным. Ошибка 429 учитывает `retry_after`; следующая статья не обгоняет неотправленную. Если Telegram явно отверг изображение с 400, функция пробует текстовое сообщение. При обрыве сети результат может быть неизвестен: запись становится `uncertain` и очередь останавливается, чтобы не отправить дубликат. Прерванная попытка старше двух минут также становится `uncertain`.

Для `uncertain` сначала сверить канал. Если сообщение есть — записать его `message_id`, `sent_at`, статус `sent`; если точно отсутствует — статус `failed`, `retry_at=now()`. Не сбрасывать статус вслепую. При изменении статуса/назначения проверять Telegram-права. Ключи не выводить в терминал и не сохранять в Git.

## Развёртывание

1. Применить только `supabase/migrations/20261025215414_news_autopublishing.sql`. Не запускать общий `db push` до сверки старого журнала миграций: см. RELEASE-2026-10-19.
2. Развернуть `news-publisher` и обновлённый `api` с выключенной JWT-проверкой шлюза. API проверяет Telegram initData; worker проверяет существующий `cron_key` в заголовке `x-cron-key`.
3. Защищённый запрос `{"mode":"inspect"}` к worker проверяет `getChat(@OGCRE8R)` и `getChatMember` бота, не отправляя сообщений. Сохранить подтверждённый числовой `chat_id` в настройку `news_publishing` с `enabled=true`.
4. Выполнить `scripts/news-publishing-schedule.sql`. Cron-команда читает секрет из `settings`; в тексте задания секрета нет. Для паузы установить `news_publishing.enabled=false`, при необходимости деактивировать `og-news-autopublish`.
5. Опубликовать frontend через GitHub/Vercel, чтобы обновить пользовательский шаринг и текст уведомления редактора.

## Проверки

`npm run test:news` — формат, длина, ссылки, PostgreSQL-очередь, права, неопределённая доставка и Telegram rate limit. `npm run test:api` — включая prepared share, защиту закрытых уроков и анонс. `npm run build` — TypeScript и production frontend.
