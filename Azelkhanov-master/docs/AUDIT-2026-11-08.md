- В GitHub workflow добавлен отдельный job мастера: собственные зависимости, unit/API/SQL/генератор, TypeScript сервера и production build. Ранее root `test:all` проверял только OG.

## Что важно при обновлении клиента

`client.mjs update` остаётся консервативным: существующие конфиги, контент и миграции защищены. В частности, `src/platform/config.ts` относится к защищённым config-файлам: установленным клиентам новый валидатор переносится вручную после сравнения, а новым клиентам включается при генерации. Базовый manifest OG не переписывался для сокрытия локальных отличий.

Сам `scripts/catalog.mjs` при явном запуске **перезаписывает** `content/catalog.json` демонстрационными материалами. Перед его запуском сохраните редакционные изменения. Обычные build/update эту команду не запускают. В сохранённом исходном каталоге есть старые даты; перед provisioning нужно проверить собственное расписание. При необходимости создайте свежий демонстрационный каталог в отдельной копии и перенесите только нужные материалы. Production-каталоги и облачная БД этим аудитом не изменялись.

## Не считать завершённой отраслевой настройкой

Fashion пока показывает общеклубные встречи в блоке примерки и демонстрационные товары с нулевой ценой. «Диагностика» эксперта открывает пример учебного квиза, а не оценку уровня. Компания использует один готовый маршрут адаптации, без выбора вариантов. В кабинете строительного проекта встречается техническая подпись `active`. Эти сценарии требуют наполнения и отдельной приёмки перед передачей реальному заказчику.

Настоящие Telegram/OIDC, платежи/возвраты, доставка сообщений, Storage, миграции и серверная авторизация на production в рамках этой проверки не изменялись и заново не принимались. Проверяйте их по `DEPLOYMENT.md` и `LIMITS.md`.
