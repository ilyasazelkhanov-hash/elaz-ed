# Azelkhanov Master

Самостоятельная мастер-платформа Telegram Mini Apps: React 19, TypeScript, Vite 8, Tailwind 4, Motion, Three.js и отдельный Supabase-проект для каждого заказчика. Бренд, модули, навигация и контент вынесены из компонентов. Демо Club, Team, Academy и Services сохраняет действия локально; производственные операции выполняет сервер.

Начните с [сценариев демонстрации](docs/SCENARIOS.md), [матрицы возможностей](docs/CAPABILITIES.md) и [протокола проверок](docs/VERIFICATION.md). Локальный адрес: `http://127.0.0.1:5180/?demo`.

Оформление по умолчанию повторяет основной OG CRE8R²: аврора-градиент, тёмная фиолетовая палитра, фон с сеткой точек, стеклянная панель-«таблетка», объёмные кнопки, Unbounded/Onest, тёмная и светлая темы. Слой стиля — `src/signature.css`, цвета — `brand.config.json`. Правила дальнейшей адаптации — [VISUAL-DESIGN.md](docs/VISUAL-DESIGN.md). Игры проверяются отдельной командой `npm run test:games`.

## Запустить мастер локально

Нужен Node.js 24+. Из этой папки:

```sh
npm ci
npm run dev
npm test
npm run build
```

Если lock-файла ещё нет, сначала `npm install`. Адрес и порт показывает Vite. Демо не подтверждает работу Telegram, платежей, очереди и облачной БД. Текущие результаты проверок и ограничения находятся в `docs/IMPLEMENTATION.md`, `docs/BACKEND-REPORT.md` и `docs/TOOLKIT-REPORT.md`.

## Собрать отдельный клиентский проект

Подготовьте JSON по образцу `brand.config.json`. `--name` — технический идентификатор из 2–64 строчных латинских букв, цифр и дефисов; отображаемое имя берётся из брендбука.

```sh
node scripts/client.mjs create --name north-club --preset club --brand ./brand.config.json --modules content,campaigns,loyalty,events,community --out ../north-club
```

Папка результата должна отсутствовать или быть пустой. Зависимости модулей добавляются автоматически; навигация и главная фильтруются. Результат включает исходники, локальный контент, публичные файлы, сервер, миграции, инструменты, тесты, документацию, конфигурацию и `.platform-kit.json` с SHA-256. Установите зависимости и выполните проверки уже внутри результата.

Генератор переносит общую реализацию модулей. Отключение модуля выполняется конфигурацией и серверными проверками, а не физическим удалением всех относящихся к нему файлов. Это не средство минимизации исходного кода.

## Обновить клиент без потери изменений

```sh
node scripts/client.mjs update --out ../north-club
node scripts/client.mjs update --out ../north-club --apply
```

Первый запуск только печатает JSON-отчёт. Второй записывает новые файлы и обновляет файлы, совпадающие с сохранённой базой. Конфиги, зависимости, контент и уже существующие миграции требуют ручного переноса изменений. Локально изменённые и неизвестные файлы сохраняются; удалённые в мастере файлы только перечисляются. Перед `--apply` сделайте резервную копию. Полная процедура: `docs/UPGRADES.md`.

## Независимая копия в OG CRE8R

```sh
node scripts/sync-og.mjs --target ..
node scripts/sync-og.mjs --target .. --apply
```

Сначала изучите отчёт. Скрипт переносит копию в `src/platform-kit`, публичные материалы в `public/platform-assets`, сервер в `server/platform-kit`, функцию `master-api` в `supabase/functions/az-master-api`. Импорты внутри копии пересчитываются; бренд копии получает цвета OG. База обновлений хранится отдельно в `.platform-kit-og.json`. Скрипт не подключает маршрут, не устанавливает пакеты и не развёртывает БД. Существующие оригиналы без базы автоматически не заменяются. Интеграцию маршрута, API URL и функций проверяйте отдельно.
