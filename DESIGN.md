# OG CRE8R: дизайн-контракт

Ориентир для изменений интерфейса, а не новый UI-kit или тема. Подготовлен 12 ноября 2026 года по исходникам `82cfcbdc4cb9d134d618ac3f1afb2d1191646e1b`. Этот SHA подтверждён в `main`; наличие коммита само по себе не подтверждает завершение deployment. Документ не является сертификатом WCAG.

## Пять решений, которые не нужно принимать заново

1. **Сначала полезное действие.** OG помогает учиться, а не демонстрирует набор виджетов. Контент, его доступность и следующий шаг важнее украшений.
2. **Компактность через иерархию.** Убираем повторяющиеся заголовки, контейнеры и пустые отступы. Не прячем полный текст, награду или CTA ради короткого скриншота.
3. **Характер, а не новый preset.** Фиолетовая редакционная типографика, мягкие поверхности и живой абстрактный пушистый Dots без рук и ног. Сохраняем узнаваемость OG.
4. **Одна система значений.** Переиспользуем семантические переменные и существующие компоненты. Исключения локальны и объяснены, не превращаются во вторую тему.
5. **Красиво в работающем состоянии.** Проверяем узкий экран, загруженные шрифты, длинный текст, конец анимационного цикла и прерванное действие. Первый удачный кадр не считается готовым дизайном.

Для границ, вуалей и дорожек используем `--color-line`, `--color-veil`, `--track`; для соответствующих цветных подложек сохраняем пары `accent/on-accent`. Цвет персонализации Dots не должен становиться цветом существенного текста. Белый текст не является универсальным решением для акцентов и градиентов.

- **Onest Variable / `--font-sans`:** чтение, подписи и управление. **Unbounded Variable / `--font-display`:** бренд и ограниченное число выразительных заголовков. **`--font-mono`:** код.
- Используем поставляемые локальные шрифты. Перед измерением layout убеждаемся, что они загружены; fallback может менять переносы.
- Текущие размеры Dots: headline 14px/1.35, пояснение 12px/1.45, CTA 12px/1.4. Это локальная плотность короткой реплики, не стандарт для статьи. Story prose сейчас 19px/1.5.
- Основной длинный текст не уменьшаем ради вместимости. Даём ему ширину, переносы и собственную прокрутку. Не распространяем display-шрифт на абзацы.
- Существующие отступы и радиусы задаются компонентами и Tailwind. Предпочитаем имеющийся 4px ритм и 20px отступы главной. Не объявляем несуществующую глобальную шкалу и не нормализуем все скругления одним массовым replace.

**Осознанное исключение:** ссылки `.prose-story a` имеют независимые тёмные чернила `#181126` и почти белую подложку `rgba(255,255,255,.94)`. Theme-violet оказался нечитаемым на ocean. Локальный контрастный контекст оправдан; обычные ссылки приложения продолжают использовать семантический токен. Подложка клонируется при переносах, underline и keyboard focus остаются. Регрессия проверяет контраст не ниже 7:1 на сегментах всех текущих story-градиентов с учётом родительской opacity .86. Это не аудит всей страницы.

## Контракты компонентов

### Dots: живой собеседник, небольшая реплика

Один непрерывный мягко-асимметричный контур с интегрированным указателем на персонажа. Не возвращаем стопку кругов, отдельный хвост из пузырей, звезду и кнопку-пилюлю внутри другой кнопки.

- На 320px персонаж остаётся рядом с репликой. Текст растёт естественно; нет фиксированной высоты, ellipsis или line-clamp.
- Вся реплика является одной настоящей кнопкой. Доступное имя включает видимые headline/moment, пояснение и действие. Внутренний CTA: текст и стрелка, не вложенный интерактивный элемент.
- Настройки и необязательный голос имеют отдельные 44px targets и реальную строку высотой не менее 44px. Отрицательные отступы не должны накладывать их на речь. Длинное имя переносится.
- SVG-декор скрыт от assistive technology и не перехватывает pointer events. Движется поверхность/персонаж, но не текстовая базовая линия и не hit target.
- Сохраняются пауза, reduced motion, невидимость страницы/элемента и covered-state. После закрытия настроек не запускается второй анимационный цикл.

Предыдущая итерация занимала 256.6px на 320px; компактная заняла 176.4px при том же cue и шрифтах. Это доказательство конкретного улучшения, **не** постоянная высота компонента. Методика: [измерение компактной реплики](docs/fixes/2026-11-12-dots-compact-conversation.md).

### Главная: одна последовательность, точные награды

Порядок: **Dots → ежедневная награда → Advent/кампания → новости**. XP находится рядом с аватаром, не в повторной большой секции «Мой прогресс».

Доступная награда, pending, полученная и ошибка остаются разными состояниями. Подтверждённый стрик заменяет награду на месте. Недельная дорожка и запас заморозок видимы компактно; meter имеет текстовое значение, а не только цвет. Визуальный refactor не меняет расчёт XP, idempotency, повтор после ошибки или смысл оплаты.

Поиск и темы допускают disclosure. Активные фильтры нельзя скрыть так, чтобы человек не понимал урезанную выдачу. Loading/error/retry остаются доступными вне закрытой панели. Сброс должен возвращать настоящий исходный набор, не только менять подпись. Сохранённые материалы и навигация не удаляются ради чистоты первого экрана.

### Курсы: динамика поддерживает содержание

Название, результат, цена/доступ и CTA важнее иллюстрации. Курсоры находятся в своей области, а не поверх текста. Это иллюстрация учебного процесса, не индикатор присутствия настоящих людей или агентов.

Проверяем **траекторию**, а не начальные координаты: подписи «ты», «проверка», результат и pause target не перекрываются во всех фазах. На узком breakpoint сначала выделяем им отдельные дорожки, только затем меняем декоративные отступы. Не уменьшаем читаемый шрифт для исправления коллизии. Цикл может повторяться, но обязан останавливаться по кнопке, offscreen/background и при reduced motion. Подробности artwork остаются в существующей системе `data-animated`, без второго независимого таймера.

### Истории и статьи: читать, управлять, перейти по ссылке

Story gradient является отдельным контрастным контекстом. Проверяем заголовки, body, ссылки, progress и кнопки, включая compositing/opacity. Подготовленные content fixtures не считаются опубликованными данными.

Длинный слайд прокручивается внутри собственного контента. Scroll, выделение, copy и link activation не должны запускать drag-to-close или случайно перелистывать историю. Previous/next, pause/play и close всегда доступны над safe area. Новый слайд начинается сверху. Автопереход учитывает длину, но никогда не заменяет ручную паузу. Возврат из фоновой вкладки не должен мгновенно пропускать непрочитанные слайды.

Продолжаем использовать существующий playback controller и его cleanup. Пунктуацию динамической прозы нормализуем через [plain-dashes](src/lib/plain-dashes.ts), не глобальной заменой DOM: код, URL и технические литералы должны остаться точными.

## Доступность и адаптивность

Цель: WCAG 2.2 AA. Для обычного текста контраст ≥4.5:1; для квалифицирующегося крупного ≥3:1; значимые границы/состояния и focus indicator ≥3:1 к соседнему цвету. Практический стандарт OG для управления: **44×44 CSS px**, это сознательно строже универсального минимума WCAG AA.

- Проверяем 320px и 390px, обе темы, длинный русский текст, длинное имя и увеличенный текст. При 200% text zoom не теряем информацию и действия. Дополнительно проверяем reflow до эквивалента 320 CSS px.
- Нет горизонтальной прокрутки страницы и обрезанного CTA. Code/table могут иметь локальную явную прокрутку. `overflow:hidden` не является исправлением переполнения; у приложения есть fixed shell, поэтому измеряем и фактический внутренний scroller.
- Сохраняем `--top`/`--bottom`, которые объединяют safe areas Telegram. Нижняя навигация не перекрывает последние controls.
- Keyboard-only: действия достижимы, фокус виден, modal корректно принимает/удерживает/возвращает фокус, Back и Escape работают по контракту экрана.
- Не используем вложенные interactive elements, перекрывающиеся hit rectangles и color-only statuses. Состояние должно иметь подпись, значок или доступное текстовое значение.
- Автоматическая смена реплик не спамит live region; пользовательское действие может дать polite announcement. Reduced motion не скрывает содержание и не отключает навигацию.

## Производительность и пределы движения

Dots является главным носителем живого характера; вторичная анимация локальна, подчинена содержанию и управляется паузой. Декорации предпочтительно меняют transform/opacity, не layout. При уходе, перекрытии, паузе и unmount останавливаем соответствующие работы и очищаем listeners/frames.

Сохраняем React/TypeScript/Vite/Tailwind и существующие motion utilities. Не добавляем daemon, Electron workspace, удалённый model proxy или библиотеку анимации только ради polish. Сначала расширяем существующий компонент. Не убираем Kazakh/Cyrillic/Latin-ext fonts, основываясь на одном скриншоте.

Для изменения ресурсов снимаем clean production build до/после одним сценарием через `scripts/perf-assets.mjs`; методика в [docs/performance/assets.md](docs/performance/assets.md). В ревью фиксируем новые JS/CSS/media bytes и причину роста. Сумма gzip не равна реальному времени загрузки. FPS, память и слабый телефон нельзя объявить проверенными по source tests. Новые бюджеты вводим после измеримого baseline, не придумываем «Lighthouse 100» или произвольный лимит килобайт.

## Как менять контракт и принимать результат

1. Назвать конкретную проблему пользователя и сохраняемое поведение. Зафиксировать один baseline SHA, cue/content, viewport, тему и font state.
2. Выбрать существующий компонент/токен. Для page override записать scope и причину. Не выбирать новый catalog preset при каждой итерации.
3. Сделать минимальное целостное изменение, воспроизвести старый дефект и проверить его исправление плюс соседние состояния из [fixture matrix](docs/design/QA-FIXTURES.md).
4. Для code changes запустить относящиеся tests, typecheck, production build и `npm run test:all`. Сохранить UI evidence отдельно от unit evidence. Documentation-only изменения валидируют свои ссылки, paths и JSON, не требуют притворного runtime-прогона.
5. Публиковать только проверенный snapshot в разрешённом scope. После публикации проверить реальный deployment SHA и узкие экраны с загруженными шрифтами. Local/demo, public и physical-device проверки обозначать раздельно.

**Stop-ship для затронутой области:** скрытое/обрезанное действие; неверный reward/access/payment state; неработающий Back/ссылка; перекрывающиеся controls; потеря текста при scroll; невозможность остановить добавленное непрерывное движение; известный контрастный дефект существенного текста. Не расширяем polish бесконечно после закрытия проверенных дефектов.
